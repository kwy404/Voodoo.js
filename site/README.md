# Voodoo.js landing page

> **JavaScript feels like magic.**

This folder is the official Voodoo.js page. It is a static site, with no build
framework and no compilation step, built with the library itself. Every counter,
every tab, every accordion and every minigame on this page runs on `v-*`
attributes, exactly as the documentation promises. If the landing page works,
the library works.

---

## Running it locally

From the repository root:

```bash
npm run build          # builds the bundles into packages/voodoojs/dist
node scripts/serve.mjs 5181
```

Open `http://localhost:5181/`.

The `scripts/serve.mjs` server has no dependencies and serves `site/` as the
root, which is exactly what the published site serves. `/examples/` resolves
because the examples live inside `site/`, so a path that works here works in
production. The only folders mounted from outside are `/brand` and `/packages`,
which the Pages workflow copies in; that list lives at the top of
`scripts/serve.mjs` and has to stay in step with `.github/workflows/pages.yml`.

## Updating the library inside the page

The landing page loads the **full build**, because it shows charts, spring
physics animation, the router, languages and the ready made components. After
any change to the package:

```bash
npm run build
cp packages/voodoojs/dist/voodoo.full.min.js     site/voodoo.full.min.js
cp packages/voodoojs/dist/voodoo.full.min.js.map site/voodoo.full.min.js.map
```

On Windows, with PowerShell:

```powershell
npm run build
Copy-Item packages\voodoojs\dist\voodoo.full.min.js     site\voodoo.full.min.js
Copy-Item packages\voodoojs\dist\voodoo.full.min.js.map site\voodoo.full.min.js.map
```

The numbers shown in the stats bar and in the comparison come from
`node scripts/size.mjs`. When the bundle size changes, update the values in
`assets/app.js`, in the `stats` object, and the `faq.a3` answer in the five
languages of `assets/i18n.js`. The directive count and the component count need
no maintenance: the page reads `V.directives.size` and `V.components.size` at
runtime.

## Publishing to Vercel

The `site/` folder is already the final result. There is no build command to run
on Vercel, only static files.

### From the dashboard

1. On vercel.com, choose **Add New** and then **Project**.
2. Import the GitHub repository.
3. Under **Framework Preset**, choose **Other**.
4. Under **Root Directory**, choose `site`.
5. Leave **Build Command** empty and tick the option to override the default.
6. Under **Output Directory**, write `.` and tick the override option.
7. Click **Deploy**.

### From the command line

```bash
npm i -g vercel
cd site
vercel            # preview
vercel --prod     # production
```

### If Vercel has to build the bundle at deploy time

When `voodoo.full.min.js` is not committed to the repository, point the project
root at the monorepo root and use:

- **Install Command:** `npm install`
- **Build Command:**
  `npm run build && cp packages/voodoojs/dist/voodoo.full.min.js* site/`
- **Output Directory:** `site`

### The examples folder

Nothing to do. The examples live at `site/examples/`, so publishing `site/` as
the output directory publishes them with it, and `/examples/` resolves the same
locally and in production.

They used to sit at the repository root, which needed a `cp -r examples
site/examples` in the build command and a matching mount in the local server.
Moving them inside `site/` removed both, and removed the class of bug where a
link worked on one and not the other.

### Domain

After the first deploy, connect the domain under **Settings**, **Domains**. The
canonical URLs written in `index.html`, in `sitemap.xml` and in the JSON-LD
point to `https://voodoojs.dev`. If the domain is a different one, change those
three places.

`vercel.json` already handles:

- security headers on every response;
- a one year cache for `voodoo.full.min.js`, whose name is stable per version;
- a one week cache for `assets/` and a one month cache for the SVGs;
- `index.html` always revalidated, so a deploy shows up straight away;
- `Access-Control-Allow-Origin` on the bundle, so it can be used as a CDN;
- the `/docs`, `/github` and `/npm` shortcuts.

## The documentation

The `docs/` folder is the project documentation in HTML, served at `/docs/`. It has no build
step: each page is a static file with an `<article class="doc-artigo">` inside, and
`assets/docs.js` builds the header, the menu, the side index, the previous and next
navigation, the syntax highlighting and the live examples around it.

**The menu is the single source of truth.** The `NAVEGACAO` list, at the top of
`docs/assets/docs.js`, defines which pages exist, in what order and in what group. A new page
goes in in three steps:

1. add `{ id: 'guia/nome', titulo: 'Page title' }` to the right group in `NAVEGACAO`;
2. create `docs/guia/nome.html` by copying the head of any neighboring page, changing the
   `<title>`, the description and the `canonical`;
3. run `npm run docs:index` to regenerate the search.

**The live examples** are the `<div data-exemplo>` blocks with a `<pre data-lang="html">` inside.
`docs.js` copies the code into an `<iframe>` with the library loaded, so what the page shows is
exactly what the code does. They load through `IntersectionObserver`, only when they get close
to the viewport, and they inherit the page theme.

Three things to watch when writing an example, all of them learned the hard way:

- **interpolation accepts objects and line breaks,** and anything that does not parse as an
  expression stays as text. A stray `{` in the middle of a sentence does not become an error.
- **a custom tag needs an explicit closing tag.** `<VInput ... />` closes nothing in HTML, and
  the rest of the block becomes a child of the component.
- **the value of `v-data` is an expression, not a block.** Methods with a body, `function` and
  `new` do not get through the parser. Anything that needs them lives in a `<script>` in the
  example itself.

**The search index** is `docs/assets/busca.js`, generated by `scripts/docs-index.mjs` from the
pages themselves: it splits each file at the headings that have an `id` and stores the title,
the section and a snippet of text. The file is loaded on demand, the first time the search field
is focused. Regenerate it whenever the text changes:

```bash
npm run docs:index
```

**Publishing.** The canonical URLs carry no `.html`, because `vercel.json` turns on `cleanUrls`.
Internal links can keep the extension: Vercel redirects. `sitemap.xml` lists the 43 pages.

## Languages

Five complete languages: Brazilian Portuguese (the default), English, Spanish,
French and German. Each one has all 375 dictionary keys filled in, with no
exceptions.

- The text lives in `assets/i18n.js` and enters the library through `V.i18n({ ... })`.
- The HTML writes the Portuguese text as the tag's real content and lets the
  `v-t` directive swap it at runtime. That serves two masters: readers without
  JavaScript, and the search engine, which indexes real text.
- The choice persists in `localStorage`, under the `voodoo:locale` key.
- The `lang` attribute on `<html>`, the `og:locale` and the `?lang=` URL
  parameter follow the active language, which makes any link shareable.
- The header picker uses its own SVG flags, not emoji: flag emoji have no glyph
  on Windows.

To add a language:

1. copy one of the blocks in `assets/i18n.js` and translate the 375 keys;
2. add the code to `LOCALES`, at the end of the same file, with the path of a
   new flag in `assets/flags/`;
3. add the `<link rel="alternate" hreflang="...">` to `index.html` and the URL
   to `sitemap.xml`.

## Theme

Dark is the brand's default theme. A script inlined in the `<head>` records and
applies the choice before the first paint, so the page never flashes in the
wrong theme. The header toggle uses `V.theme`, which keeps the preference in
`localStorage`, under the `voodoo:theme` key.

The preview frames inherit the page theme.

## Details worth knowing before you edit

**The `v-*` attributes disappear from the HTML.** Once Voodoo.js has processed
an element, it keeps the attributes in memory and removes them from the
document. No CSS rule can depend on `[v-...]`. Use classes, or `data-*`, which
stay. The page itself has a section explaining this.

**The library loads with `data-manual`.** With `defer`, `document.readyState` is
already `interactive` when the library evaluates, and the automatic start would
happen before `i18n.js`, `playground.js` and `app.js` register the data, the
examples and the playground component. That is why the order is:

```html
<script src="voodoo.full.min.js" data-manual defer></script>
<script src="assets/i18n.js" defer></script>
<script src="assets/playground.js" defer></script>
<script src="assets/app.js" defer></script>
```

and the one calling `V.start()` is the last line of `app.js`. Any new script
that registers components, directives or data has to come in **before**
`app.js`.

**Interpolation accepts nested braces and several lines.** `{ $t('chave', { n: 1 }) }` works,
because the scan counts the brace levels. Anything that does not parse as an expression stays
as text.

**Braces inside text that is not an expression.** Voodoo.js does not interpolate
inside `<pre>` and `<code>`. Every code block on the page sits in
`<pre v-ignore><code data-hl="...">`, and `v-ignore` stops the walker from
descending into the tree after the syntax highlighting has created the `<span>`s.

**Syntax highlighting.** `assets/app.js` walks the elements that have `data-hl`
and replaces their content with colored `<span>`s. This happens before
`V.start()`, on purpose.

## SEO

- A title and description of their own per language, swapped at runtime.
- Full Open Graph, Twitter Card `summary_large_image`.
- `canonical` and `hreflang` for the five languages, plus `x-default`.
- JSON-LD with `SoftwareApplication`, `FAQPage` and `BreadcrumbList`.
- A single `<h1>`, with the heading hierarchy in order.
- Valid `robots.txt` and `sitemap.xml`.
- Critical CSS inlined, fonts with `font-display: swap`, images with `alt`,
  `loading="lazy"` and declared dimensions.
- Accessibility: visible focus, keyboard navigation, `aria-label` where text is
  missing, contrast checked in both themes and `prefers-reduced-motion`
  respected.
