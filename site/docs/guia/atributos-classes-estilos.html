Fundamentos

Atributos, classes e estilos

Não é só o texto que muda. O href, o src, o disabled, a classe e a cor também precisam acompanhar o estado. Um dois pontos na frente do nome liga qualquer atributo de qualquer tag.

Qualquer atributo, qualquer tag

<img :src="foto" :alt="descricao" :width="largura">
<a :href="'/produto/' + id" :target="novaAba ? '_blank' : '_self'">Ver</a>
<input :placeholder="'Buscar entre ' + produtos.length + ' itens'">
<div :aria-label="rotulo" :data-estado="situacao" :title="dica"></div>
<circle :r="raio" :fill="cor"></circle>
<minha-tag :dado="valor"></minha-tag>

Vale para atributos comuns, de acessibilidade, de dados, de SVG e de tags próprias. A forma longa é v-bind:nome; as duas fazem a mesma coisa. 

<div v-data="{ raio: 30, cor: '#6d3bf5', rotulo: 'Círculo roxo' }">
  <div class="linha">
    <input type="range" min="10" max="45" v-model.number="raio">
    <input type="color" v-model="cor">
  </div>
  <svg width="100" height="100" role="img" :aria-label="rotulo">
    <circle cx="50" cy="50" :r="raio" :fill="cor"></circle>
  </svg>
</div>

Atributos que são ligados ou desligados

<div v-data="{ carregando: false }">
  <label><input type="checkbox" v-model="carregando"> carregando</label>
  <p><button :disabled="carregando">Salvar</button></p>
  <p><input :readonly="carregando" value="um campo"></p>
</div>

Quando o valor é falso, o atributo some do HTML em vez de virar a palavra false — que, para o navegador, seria tão verdadeira quanto qualquer outra. A Voodoo trata assim disabled, checked, readonly, required, selected, hidden, open, multiple, autofocus, novalidate e inert.

Classes

<style>
  .cartao { padding: .6rem; border: 1px solid #3d3560; border-radius: 8px }
  .ativo  { border-color: #2ed9a5 }
  .erro   { border-color: #ff3d8b }
</style>

<div v-data="{ selecionado: false, temErro: false }">
  <div class="linha">
    <label><input type="checkbox" v-model="selecionado"> selecionado</label>
    <label><input type="checkbox" v-model="temErro"> erro</label>
  </div>
  <div class="cartao" :class="{ ativo: selecionado, erro: temErro }">
    A classe "cartao" nunca é removida.
  </div>
</div>

A forma de objeto liga cada classe a uma condição. A forma de lista aceita textos e objetos misturados: 

<div :class="['base', tema, { grande: expandido }]"></div>
O que já estava escrito continua lá

As classes escritas no class são sempre preservadas. O :class só acrescenta e remove as que ele mesmo controla, então ele convive com CSS de terceiros e com classes adicionadas por outro código.

Estilos

<div v-data="{ cor: '#2ed9a5', largura: 60 }">
  <div class="linha">
    <input type="color" v-model="cor">
    <input type="range" min="10" max="100" v-model.number="largura">
  </div>
  <div :style="{ background: cor, width: largura + '%', height: '2rem', borderRadius: '6px' }"></div>
</div>

A forma de texto também vale, e propriedades customizadas passam intactas: 

<div :style="'width: ' + largura + 'px'"></div>
<div :style="{ '--v-primary': corDaMarca }"></div>

Nomes em camelCase viram traço: borderRadius chega ao CSS como border-radius.

Vários de uma vez, e propriedades

<input v-bind="{ placeholder: 'Nome', maxlength: '10', required: true }">
<video .currentTime="segundos"></video>

v-bind sem argumento aplica um objeto inteiro — útil quando as opções vêm de uma variável, ou quando um componente repassa props. O ponto na frente do nome escreve na propriedade do elemento em vez do atributo, que é o que resolve casos como currentTime, value e indeterminate, onde o atributo e a propriedade não são a mesma coisa.

Os atributos somem depois

Vale repetir

Depois que a página monta, :class, :style, v-show e os demais atributos v-* saem do HTML. O resultado do que eles fizeram permanece — a classe está aplicada, o estilo está no elemento —, mas o atributo em si não existe mais. Nunca escreva CSS apoiado em seletores como [v-show], e nunca procure por eles com querySelectorAll.

Pegando o elemento em si

Quando o que você precisa é do elemento, e não de um atributo dele, o v-ref guarda a referência em $refs: 

<div v-data="{}">
  <input v-ref="busca" placeholder="Vou receber o foco">
  <button @click="$refs.busca.focus()">Focar o campo</button>
  <button @click="$refs.busca.value = ''">Limpar</button>
</div>

Mandando o elemento para outro lugar

Um modal escrito no meio da página costuma esbarrar em overflow: hidden e em z-index de um ancestral. O v-teleport move o elemento no documento sem que ele perca o escopo de onde veio: 

<div v-teleport="body">Este bloco vai para o final do body</div>
<div v-teleport="#area-de-modais">Este vai para um container específico</div>
