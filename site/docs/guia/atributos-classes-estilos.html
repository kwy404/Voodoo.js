Fundamentals

Attributes, classes and styles

It is not only the text that changes. The href, the src, the disabled, the class and the colour have to follow the state too. A colon in front of the name binds any attribute of any tag.

Any attribute, any tag

<img :src="photo" :alt="description" :width="width">
<a :href="'/product/' + id" :target="newTab ? '_blank' : '_self'">View</a>
<input :placeholder="'Search among ' + products.length + ' items'">
<div :aria-label="label" :data-state="status" :title="hint"></div>
<circle :r="radius" :fill="colour"></circle>
<my-tag :item="value"></my-tag>

It holds for ordinary attributes, accessibility attributes, data attributes, SVG attributes and attributes of tags of your own. The long form is v-bind:name; the two do the same thing. 

<div v-data="{ radius: 30, colour: '#5b2ee5', label: 'A purple circle' }">
  <div class="linha">
    <input type="range" min="10" max="45" v-model.number="radius">
    <input type="color" v-model="colour">
  </div>
  <svg width="100" height="100" role="img" :aria-label="label">
    <circle cx="50" cy="50" :r="radius" :fill="colour"></circle>
  </svg>
</div>

Attributes that are either on or off

<div v-data="{ loading: false }">
  <label><input type="checkbox" v-model="loading"> loading</label>
  <p><button :disabled="loading">Save</button></p>
  <p><input :readonly="loading" value="a field"></p>
</div>

When the value is false, the attribute leaves the HTML instead of becoming the word false — which, to the browser, would be as true as anything else. Voodoo treats disabled, checked, readonly, required, selected, hidden, open, multiple, autofocus, novalidate and inert this way.

Classes

<style>
  .card   { padding: .6rem; border: 1px solid var(--line); border-radius: 8px }
  .active { border-color: var(--accent) }
  .error  { border-color: var(--ink); border-style: dashed }
</style>

<div v-data="{ selected: false, hasError: false }">
  <div class="linha">
    <label><input type="checkbox" v-model="selected"> selected</label>
    <label><input type="checkbox" v-model="hasError"> error</label>
  </div>
  <div class="card" :class="{ active: selected, error: hasError }">
    The "card" class is never removed.
  </div>
</div>

The object form ties each class to a condition. The list form takes strings and objects mixed together: 

<div :class="['base', theme, { large: expanded }]"></div>
What was already written stays there

The classes written in class are always preserved. :class only adds and removes the ones it controls itself, so it lives happily with third-party CSS and with classes added by other code.

Styles

<div v-data="{ colour: '#5b2ee5', width: 60 }">
  <div class="linha">
    <input type="color" v-model="colour">
    <input type="range" min="10" max="100" v-model.number="width">
  </div>
  <div :style="{ background: colour, width: width + '%', height: '2rem', borderRadius: '6px' }"></div>
</div>

The string form works too, and custom properties come through untouched: 

<div :style="'width: ' + width + 'px'"></div>
<div :style="{ '--v-primary': brandColour }"></div>

camelCase names turn into dashes: borderRadius reaches the CSS as border-radius.

Several at once, and properties

<input v-bind="{ placeholder: 'Name', maxlength: '10', required: true }">
<video .currentTime="seconds"></video>

v-bind with no argument applies a whole object — handy when the options come from a variable, or when a component passes props along. The dot in front of the name writes to the element's property instead of its attribute, which is what settles cases like currentTime, value and indeterminate, where the attribute and the property are not the same thing.

The attributes disappear afterwards

Worth repeating

Once the page mounts, :class, :style, v-show and the other v-* attributes leave the HTML. The result of what they did stays — the class is applied, the style is on the element — but the attribute itself no longer exists. Never write CSS that leans on selectors like [v-show], and never look for them with querySelectorAll.

Getting hold of the element itself

When what you need is the element, and not an attribute of it, v-ref keeps the reference in $refs: 

<div v-data="{}">
  <input v-ref="search" placeholder="I am about to get the focus">
  <button @click="$refs.search.focus()">Focus the field</button>
  <button @click="$refs.search.value = ''">Clear</button>
</div>

Sending the element somewhere else

A modal written in the middle of the page tends to run into an ancestor's overflow: hidden and z-index. v-teleport moves the element within the document without it losing the scope it came from: 

<div v-teleport="body">This block goes to the end of the body</div>
<div v-teleport="#modal-area">This one goes to a specific container</div>
