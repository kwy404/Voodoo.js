Dados e formulários

Buscando dados de um servidor

Buscar dados, enviar um formulário, excluir um registro. Normalmente isso vira fetch, then, montagem manual de HTML e tratamento de erro repetido em toda tela. Na Voodoo é um atributo.

Sobre os exemplos desta página

Os blocos aqui não rodam ao vivo como nas outras páginas: eles precisariam de um servidor de verdade do outro lado. As URLs são fictícias — troque por endereços da sua API.

Os cinco verbos

<button v-get="/api/usuarios" v-target="#lista">Carregar</button>

<div id="lista"></div>

Existem v-get, v-post, v-put, v-patch e v-delete. Cada elemento tem um gatilho natural: um <form> dispara no submit, um campo dispara no change, e todo o resto dispara no click.

A URL pode ser fixa ou uma expressão:

<button v-delete="'/api/usuarios/' + u.id"
        v-confirm="Excluir usuário?"
        v-toast-success="Usuário excluído!">Excluir</button>

O que acontece com a resposta

Se o servidor devolve HTML, ele entra direto no alvo. Se devolve JSON, a Voodoo transforma em HTML legível: uma lista de objetos vira tabela, um objeto vira lista de definições, e todos os valores são escapados no caminho.

Se você prefere controlar o formato, aponte um <template> da própria página: 

<button v-get="/api/usuarios" v-target="#lista" v-template="#linha">Carregar</button>

<template id="linha">
  <li><strong>{ nome }</strong> <small>{ email }</small></li>
</template>

<ul id="lista"></ul>

E se você não quer HTML nenhum, só o dado no estado, o v-as escreve na variável e o resto da página reage como reagiria a qualquer outra mudança: 

<div v-data="{ usuarios: [] }">
  <button v-get="/api/usuarios" v-as="usuarios">Carregar</button>
  <ul>
    <li v-for="u in usuarios" :key="u.id">{ u.nome }</li>
  </ul>
</div>

Onde o resultado é colocado

v-target é o seletor do elemento que recebe. Sem ele, o alvo é o próprio elemento. v-swap decide como: 

<button v-get="/api/comentarios?pagina=2" v-target="#comentarios" v-swap="append">
  Carregar mais
</button>

Modos aceitos: innerHTML (o padrão), outerHTML, replace, textContent, beforebegin, afterbegin, beforeend, afterend, append, prepend, delete e none.

Outros gatilhos

<div v-get="/api/status" v-poll="5s" v-target="#status"></div>
<div v-load-visible="/api/comentarios"></div>
<input v-search="/api/produtos" v-param="q" v-target="#resultados" v-debounce="300">
<div v-get="/api/banner" v-trigger="visible"></div>
  • v-poll repete em intervalo fixo e pausa quando a aba não está visível.
  • v-load-visible busca quando o elemento chega perto da tela.
  • v-search faz busca enquanto o usuário digita, com v-param para o nome do parâmetro e v-min-length para o mínimo de caracteres.

Carregando, erro, e o que fazer depois

<button v-get="/api/relatorio"
        v-target="#saida"
        v-loading="#spinner"
        v-disable-loading
        v-on-success="$toast.success('Pronto!')"
        v-on-error="console.warn($detail)">
  Gerar
</button>

<div id="spinner">Gerando relatório...</div>

Durante a requisição o elemento ganha a classe v-loading e o atributo aria-busy="true" — as duas coisas dão gancho para o CSS e para leitores de tela sem nenhum código a mais. Uma nova requisição do mesmo elemento cancela a anterior que ainda estiver pendente, o que resolve sozinho o clique repetido.

v-resource: dados, carregando e erro em uma linha

Quando você quer o estado da requisição disponível no HTML, e não só o resultado: 

<div v-resource="produtos: /api/produtos">

  <p v-if="produtos.loading">Carregando...</p>
  <p v-else-if="produtos.error">Falhou: { produtos.error.message }</p>

  <ul v-else>
    <li v-for="p in produtos.data" :key="p.id">{ p.nome }</li>
  </ul>

  <button @click="produtos.reload()">Atualizar</button>
</div>

A sintaxe é nome: url. O objeto criado tem data, loading, error, loaded, reload() e set(). Ele aceita v-method, v-params, v-cache, v-retry, v-timeout, v-json-path, v-poll e v-manual, que segura a primeira busca até você chamar reload().

O mesmo, em JavaScript

const usuarios = await V.http.get('/api/users', { params: { pagina: 2 }, cache: 60000 });
await V.http.post('/api/users', { nome: 'Ana' });
await V.http.upload('/api/arquivos', formData, { onProgress: (p) => console.log(p) });

V.http.setBaseURL('https://api.exemplo.com');
V.http.setToken('meu-jwt');
V.http.interceptors.response.use((r) => r);

A superfície completa — interceptadores, cache, cancelamento, HttpError e upload com progresso — está na referência do cliente HTTP.

CSRF sem configurar nada

Métodos que escrevem levam o token de <meta name="csrf-token"> no cabeçalho X-CSRF-TOKEN automaticamente. Se o seu servidor usa outro nome de cabeçalho, ajuste por um interceptador de requisição.

Detalhe conhecido

v-confirm no mesmo elemento de um verbo HTTP pergunta duas vezes. Use v-confirm junto de v-click, ou peça a confirmação dentro da própria expressão com $confirm(...).
