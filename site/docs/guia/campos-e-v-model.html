Fundamentals

Form fields with v-model

A field has to reflect the state, and the state has to reflect the field. v-model does both directions at once, on any kind of field, and converts the value according to what that field is.

Every kind of field

<div v-data="{ name: '', bio: '', accepted: false, state: 'SP', tags: [], payment: 'pix' }">
  <div class="linha"><input v-model="name" placeholder="Name"></div>
  <div class="linha"><textarea v-model="bio" placeholder="Bio"></textarea></div>

  <div class="linha">
    <label><input type="checkbox" v-model="accepted"> I accept the terms</label>
  </div>

  <div class="linha">
    <select v-model="state"><option>SP</option><option>RJ</option><option>MG</option></select>
  </div>

  <div class="linha">
    <label><input type="checkbox" value="js" v-model="tags"> js</label>
    <label><input type="checkbox" value="css" v-model="tags"> css</label>
  </div>

  <div class="linha">
    <label><input type="radio" value="pix" v-model="payment"> Pix</label>
    <label><input type="radio" value="card" v-model="payment"> Card</label>
  </div>

  <p v-text="JSON.stringify({ name, accepted, state, tags, payment })"></p>
</div>

FieldValue in state

Modifiers

<input v-model.number="age">
<input v-model.trim="email">
<textarea v-model.lazy="bio"></textarea>
<input v-model.debounce="search" v-debounce="600">
<input type="file" v-model.single="photo">
ModifierEffect
.numberConverts to a number. Text that does not become a number stays as it is
.trimStrips the spaces off both ends
.lazyWrites on change, not on every keystroke
.debounceWaits for the user to stop typing; the delay comes from v-debounce
.singleOn a file field, keeps the first file instead of the list
 
<div v-data="{ age: 0, email: '', search: '' }">
  <div class="linha"><input type="number" v-model.number="age">
    <span>Ten years from now: { age + 10 }</span></div>
  <div class="linha"><input v-model.trim="email" placeholder="  with spaces  ">
    <span>[{ email }]</span></div>
  <div class="linha"><input v-model.debounce="search" v-debounce="600" placeholder="Search">
    <span>{ search }</span></div>
</div>

Without .number, an <input type="number"> still writes a number: conversion by field type happens on its own. The modifier is there to force the conversion on ordinary text fields.

Binding to a path, not to a variable

v-model works on any assignable expression, not only on a loose variable. That keeps you from scattering a form across ten loose keys when it is, in fact, one object. 

<div v-data="{ form: { name: '', address: { city: '', state: '' } } }">
  <div class="linha"><input v-model="form.name" placeholder="Name"></div>
  <div class="linha">
    <input v-model="form.address.city" placeholder="City">
    <input v-model="form.address.state" placeholder="State">
  </div>
  <p v-text="JSON.stringify(form)"></p>
</div>

Inside a v-for, the same holds for the iteration item: <input v-model="task.text"> writes into the right object of the list.

Reacting to typing

v-watch observes the v-model of the same element and hands you $value and $old. It is the short road to firing a search or a calculation when the field changes, without writing a separate event. 

<div v-data="{ search: '', history: [] }">
  <input v-model.debounce="search" v-debounce="500"
         v-watch="$value && history.unshift($value)" placeholder="Type and stop">
  <ul><li v-for="(t, i) in history.slice(0, 5)">{ t }</li></ul>
</div>
