Componentes e estado

Componentes prontos

O build completo registra 29 componentes com aparência própria, acessíveis e alinhados ao tema. Nenhum deles usa a aparência padrão do navegador, e nenhuma cor está fixa no CSS: tudo vem da paleta, que você troca em uma linha.

Só no voodoo.full.min.js

Os componentes V* existem apenas no build completo. Nos outros dois arquivos as tags simplesmente não são reconhecidas e ficam no HTML como estão.

Usando

<div v-data="{ email: '' }">
  <VButton variant="primary" size="lg" icon="check">Salvar</VButton>
  <VButton variant="ghost">Cancelar</VButton>
  <VBadge tone="success">Ativo</VBadge>
  <VTag>rascunho</VTag>

  <VInput label="E-mail" type="email" icon="mail"
          hint="Nunca compartilhamos" v-model="email"></VInput>

  <VAlert tone="warning" title="Atenção" closable>
    A cobrança vence em três dias.
  </VAlert>

  <VStat label="Receita" value="R$ 128.400" delta="12.4" icon="chart"></VStat>
</div>

Cada um aceita as duas escritas, <VButton> e <v-button>. As props booleanas aceitam o atributo vazio, o texto true e a ligação reativa :loading="salvando".

Feche sempre a tag

Estes componentes são tags próprias, e o HTML não aceita fechamento automático fora das tags conhecidas: <VInput ... /> não fecha nada, e o navegador coloca todo o resto do bloco dentro do componente. Escreva sempre <VInput ...></VInput>. O sintoma, quando isso passa despercebido, é um trecho da página que some sem erro nenhum no console.

Tabela e paginação

<div v-data="{ pedidos: [
  { nome: 'Ana',  total: 'R$ 1.200' },
  { nome: 'Beto', total: 'R$ 890' },
  { nome: 'Cris', total: 'R$ 2.310' }
] }">
  <VTable columns="nome:Cliente, total:Total:right" :rows="pedidos" striped></VTable>
</div>

A escrita de columns é chave:Título:alinhamento, separada por vírgulas. As linhas vêm de qualquer array reativo — inclusive o de um v-resource, o que dá uma tabela ligada à API sem nenhum código de montagem.

Dentro de um formulário

Eles funcionam com v-submit e v-validate sem nenhuma adaptação: o que chega ao servidor é o mesmo que chegaria de campos comuns, porque por baixo são campos comuns. 

<form v-submit="/api/inscricoes" v-validate v-toast-success="Inscrição enviada!">
  <VInput label="Nome" name="nome" required></VInput>
  <VInput label="E-mail" name="email" type="email" required></VInput>
  <VSelect label="Plano" name="plano" options="Mensal, Anual" required></VSelect>
  <VCheckbox name="termos" label="Aceito os termos" required></VCheckbox>
  <VButton type="submit" :loading="$form.loading">Enviar</VButton>
</form>

A paleta

A escala de tons é gerada a partir das suas cores, então trocar a cor da marca troca a interface inteira — botões, campos, avisos, gráficos e os componentes de interface do build essencial junto. 

V.palette({ primary: '#0F766E', accent: '#F59E0B', radius: '10px' });
<div>
  <script>
    V.config.globals.aplicarPaleta = (cor) => V.palette({ primary: cor });
  </script>

  <div v-data="{ cor: '#0f766e' }">
    <div class="linha">
      <input type="color" v-model="cor">
      <button @click="aplicarPaleta(cor)">Aplicar na paleta</button>
    </div>
    <VButton variant="primary">Botão primário</VButton>
    <VBadge tone="primary">Etiqueta</VBadge>
  </div>
</div>
Por que o exemplo passa por uma função

O objeto V não existe dentro das expressões: elas só enxergam os escopos, as variáveis mágicas e uma lista fechada de globais. Para chamar a biblioteca de dentro do HTML, publique a função em V.config.globals, como acima. A referência de expressões explica o porquê e lista o que é permitido.

A página de tema e paleta mostra os tokens gerados, o tema claro e escuro, e como usar as mesmas variáveis no seu próprio CSS.
