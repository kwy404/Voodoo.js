Componentes e estado

Componentes: props, slots, eventos e ciclo de vida

O mesmo cartão aparece em cinco lugares da página. Copiar e colar HTML não escala. Registre uma vez, use como tag — e continue sem passo de build, porque o template é uma string de HTML comum.

Registrando

V.component('cartao-usuario', {
  props: {
    nome: { type: 'string', default: 'sem nome' },
    idade: { type: 'number', default: 0 }
  },
  state(props) {
    return { curtidas: 0 };
  },
  computed: {
    resumo() { return `${this.nome}, ${this.idade} anos`; }
  },
  methods: {
    curtir() { this.curtidas++; this.emit('curtido', this.curtidas); }
  },
  mounted() { console.log('montado', this.nome); },
  template: `
    <article>
      <h3>{ resumo }</h3>
      <slot></slot>
      <button @click="curtir()">Curtir ({ curtidas })</button>
    </article>
  `
});

Três escritas usam o mesmo componente:

<CartaoUsuario nome="Ana" :idade="idadeDaAna" @curtido="registrar($detail)">
  <p>Este conteúdo entra no slot.</p>
</CartaoUsuario>

<cartao-usuario nome="Bia"></cartao-usuario>
<div v-component="cartao-usuario" nome="Cris"></div>

E funcionando de verdade, com o registro e o uso no mesmo bloco:

<div>
  <script>
    V.component('contador-simples', {
      props: { titulo: { type: 'string', default: 'Contador' } },
      state: () => ({ n: 0 }),
      computed: { dobro() { return this.n * 2 } },
      methods: { somar() { this.n++; this.emit('mudou', this.n) } },
      template: '<p><b>{ titulo }</b>: { n } (dobro { dobro }) ' +
                '<button @click="somar()">+1</button></p>'
    });
  </script>

  <div v-data="{ ultimo: 0 }">
    <contador-simples titulo="Visitas" @mudou="ultimo = $detail"></contador-simples>
    <contador-simples titulo="Cliques" @mudou="ultimo = $detail"></contador-simples>
    <p>O último valor emitido foi { ultimo }.</p>
  </div>
</div>

Os dois contadores têm estado próprio, e o escopo de fora só sabe deles pelo evento que eles emitem. É essa separação que faz o componente valer a pena.

Props

Props estáticas vêm por atributo, props dinâmicas por :prop. Os tipos aceitos são string, number, boolean, array, object e any, e o valor do atributo é convertido sozinho. 

<cartao titulo="Faturamento" total="1200" ativo></cartao>
<cartao :titulo="painel.nome" :total="painel.receita" :ativo="painel.ligado"></cartao>

Os três nomes user-name, username e userName chegam todos como userName, o que evita a discussão sobre qual escrita usar no HTML.

Quando o tipo não importa, existe a forma curta:

V.component('saudacao', {
  props: ['nome', 'idade'],
  template: '<p>{ nome } tem { idade } anos</p>'
});

Slots

V.component('painel', {
  template: `
    <section>
      <header><slot name="cabecalho"><h3>Sem título</h3></slot></header>
      <div><slot></slot></div>
      <footer><slot name="rodape"></slot></footer>
    </section>
  `
});
<painel>
  <h3 slot="cabecalho">Relatório</h3>
  <p>Este parágrafo cai no slot padrão.</p>
  <button slot="rodape">Fechar</button>
</painel>

O conteúdo escrito dentro de um <slot> no template é o valor padrão, usado quando ninguém preenche. E o conteúdo do slot é avaliado no escopo de quem escreveu a tag, não no do componente — então ele enxerga as variáveis do lugar onde está, como qualquer HTML normal enxergaria.

Eventos

methods: {
  confirmar() { this.emit('confirmado', { id: this.id }); }
}
<dialogo @confirmado="registrar($detail)"></dialogo>

emit dispara um CustomEvent que sobe pela árvore, e o que você passar como segundo argumento chega em $detail. É o mesmo mecanismo do $dispatch, o que significa que um ancestral qualquer pode escutar o evento sem precisar ser o pai imediato.

Ciclo de vida e instância

Os ganchos são beforeMount, mounted, updated, beforeUnmount e unmounted. Dentro dos métodos, this tem $el, $props, $refs, $scope, $parent, $name, emit(), $watch() e $nextTick(). 

<div>
  <script>
    V.component('relogio', {
      state: () => ({ agora: new Date() }),
      mounted() {
        this.timer = setInterval(() => { this.agora = new Date() }, 1000);
      },
      beforeUnmount() { clearInterval(this.timer) },
      template: '<time>{ agora.toLocaleTimeString() }</time>'
    });
  </script>

  <div v-data="{ ligado: true }">
    <button @click="ligado = !ligado">Ligar e desligar</button>
    <p><relogio v-if="ligado"></relogio></p>
  </div>
</div>

O beforeUnmount existe justamente para casos como esse: sem ele, o setInterval continuaria rodando depois que o elemento saísse da tela.

O componente não enxerga o escopo de fora

Proposital

Por padrão um componente não enxerga o v-data que o envolve, para que ele não dependa de onde foi colocado. Tudo o que ele precisa entra por prop. Quando você quer o contrário — normalmente em componentes internos de uma página só —, declare inheritScope: true na definição.

Quando vale a pena

SituaçãoUse
O mesmo HTML se repete com dados diferentesComponente
O trecho aparece uma vez sóv-data, sem componente
Você precisa do mesmo estado em lugares distantesStore
É um controle comum de interfaceComponente pronto, se já existir
É um comportamento, e não uma estruturaDirective própria

Onde registrar

O registro precisa acontecer antes de a biblioteca varrer a página, senão ela passa por uma tag que ainda não conhece. Com data-manual, isso é simples de garantir: 

<script src="voodoo.min.js" data-manual defer></script>
<script src="componentes.js" defer></script>
<script defer>V.start();</script>

Um componente registrado depois disso ainda funciona para HTML criado a partir daquele momento, porque o observador do DOM continua ativo — mas as tags que já estavam na página não voltam atrás sozinhas. Nesse caso, chame V.refresh().
