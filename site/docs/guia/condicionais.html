Fundamentals

Conditionals

Part of the page should only show up in certain situations. There are two roads to that, and the choice between them changes performance and what happens to the state of whatever is inside.

v-show toggles the CSS

<div v-data="{ open: false }">
  <button @click="open = !open">Details</button>
  <div v-show="open">This block stays in the DOM the whole time.</div>
</div>

v-show only touches display. The element never leaves the document: it exists, it holds its place in the tree, it keeps whatever was typed inside it and it stays reachable by querySelector.

v-if inserts and removes

<div v-data="{ grade: 7 }">
  <input type="range" min="0" max="10" v-model.number="grade">
  <p>Grade: { grade }</p>
  <p v-if="grade >= 9">Excellent</p>
  <p v-else-if="grade >= 6">Good</p>
  <p v-else>Needs work</p>
</div>

v-if really does create and destroy the element. What stays in its place is a comment node, which the library uses as an anchor to know where to reinsert once the condition becomes true again.

Immediate siblings

v-else-if and v-else have to be immediate siblings of the v-if, with nothing in between. An HTML comment between them breaks the chain, and the v-else becomes a loose element that is always visible.

Conditioning a group without inventing a div

When what you want to hide is several sibling elements, and wrapping them in a <div> would wreck the layout — inside a table, a list or a grid — use <template>. It becomes no element at all on screen. 

<div v-data="{ loaded: true }">
  <button @click="loaded = !loaded">Toggle</button>
  <template v-if="loaded">
    <h4>Title</h4>
    <p>Both elements appear and disappear together, with no wrapper.</p>
  </template>
</div>

Which one to use

SituationUse
Toggles often, like an accordionv-show
Almost never shows up, or is heavyv-if
Has to unmount what is insidev-if
Has to keep the state of what is insidev-show
Depends on data that has not arrived yetv-if

The difference is visible in a text field. Type into both and toggle: 

<div v-data="{ visible: true }">
  <button @click="visible = !visible">Hide and show</button>

  <div v-show="visible">
    <label>with v-show <input placeholder="type here"></label>
  </div>

  <div v-if="visible">
    <label>with v-if <input placeholder="type here"></label>
  </div>
</div>

The v-show field remembers what was typed. The v-if one comes back empty, because the element stopped existing and a new one was created in its place.

Hiding until the library starts

Before Voodoo mounts, the raw HTML shows for an instant — braces and all, with the v-else visible next to the v-if. v-cloak solves it: the library removes the attribute when it finishes that stretch. 

<style>
  [v-cloak] { display: none !important; }
</style>

<div v-cloak v-data="{ ready: false }">
  <p v-if="ready">Ready</p>
  <p v-else>Loading...</p>
</div>

Conditions that do not come from state

Some common conditions have a directive of their own, and save you from keeping information in state that the browser already has:

DirectiveShows when
v-onlineThe browser has a connection
v-offlineThe browser has no connection
v-visibleThe element enters the viewport, handy for animating on scroll
v-idleThe user has been idle for the time given
v-loadingA request from that element is in flight

And, inside any expression, $screen, $network and $device answer about screen size, connection and kind of device: 

<div v-data="{}">
  <p v-show="$screen.mobile">You are on a small screen.</p>
  <p v-show="!$screen.mobile">You are on a large screen.</p>
  <p v-show="!$network.online">You are offline.</p>
</div>
