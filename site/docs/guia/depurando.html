Estendendo e depurando

Depurando problemas comuns

Esta página é uma lista de sintomas. Cada um vem com o que ele costuma significar e o que fazer a respeito — a maioria não é bug, e sim uma decisão de projeto encontrando alguém que ainda não a conhecia.

Nada acontece, o HTML aparece cru

Confira, nesta ordem: o arquivo carregou (a aba de rede responde em um segundo); ele não está com data-manual sem uma chamada a V.start(); e o console não tem erro de sintaxe de expressão, que aparece com a posição exata.

Se a página usa componentes ou directives próprias registradas em outro arquivo, o registro precisa acontecer antes do V.start().

O conteúdo pisca antes de renderizar

<style>[v-cloak] { display: none !important; }</style>
<div v-cloak v-data="{}">...</div>

Meu CSS parou de funcionar

Quase sempre é um seletor apoiado em atributo v-*. Depois que a biblioteca processa o elemento, o atributo sai do documento, e [v-tab] { ... } deixa de casar com qualquer coisa. Pelo mesmo motivo, el.getAttribute('v-algo') devolve null e querySelectorAll('[v-show]') devolve vazio.

Use classes ou data-*. Se você precisa mesmo do comportamento antigo, V.config.cleanAttributes = false — ou data-keep-attributes na tag do script — mantém tudo no HTML.

O valor muda mas a tela não

Três causas, em ordem de frequência:

  • Erro de digitação no nome. Escrever em uma chave que não existe cria a chave no escopo local, sem erro nenhum. Ligue data-devtools para transformar esses casos em aviso.
  • Você leu de uma fonte que não é reativa. $storage.get(...), $cookie.get(...) e $url.get(...) leem no momento em que a expressão roda, e nada avisa a tela depois. Guarde o valor no escopo, ou use um store com persist.
  • É um getter dentro de um store. Uma propriedade declarada com get é resolvida uma vez, na criação. Para valores derivados, use um método.

Maximum call stack, ou aviso de laço no console

Algum efeito está escrevendo na mesma chave que lê. O agendador interrompe a repetição e avisa. Reveja a expressão: costuma ser um v-effect que atribui a uma variável que ele mesmo lê.

O v-for perde o foco do campo quando a lista muda

Falta :key. Sem chave, a biblioteca só conhece a posição, e reordenar recria os elementos. Com :key="item.id", eles são reaproveitados e movidos. A chave precisa ser estável: o índice não serve, porque ele muda junto com a ordem.

v-if e v-for no mesmo elemento não funcionam

Os dois assumem o controle do nó. Ponha a condição em um filho, ou filtre na própria expressão do v-for. A página de listas mostra as duas formas.

window, document e fetch são undefined nas expressões

É proposital: apenas uma lista fechada de globais é liberada, e é isso que permite rodar sob Content Security Policy restritiva. Para chegar ao DOM e a serviços, use as magias — $el, $refs, $http, $storage, $clipboard. Para liberar algo seu: 

V.config.globals.minhaFuncao = minhaFuncao;

O objeto V também não está disponível dentro das expressões, pelo mesmo motivo.

Como escrevo uma função com várias linhas em um atributo?

Não escreva. O parser aceita expressões, não blocos. Coloque a lógica em um método do v-data, de um store ou do escopo raiz: 

V.data({ limpar() { this.itens = []; this.total = 0; } });
<button @click="limpar()">Limpar</button>

O componente não enxerga o v-data em volta

É o comportamento padrão: componentes isolam o escopo, para não dependerem por acidente do lugar onde foram colados. Passe o valor por prop, ou declare inheritScope: true na definição.

O contrário também confunde: o conteúdo de um <slot> pertence ao escopo de quem escreveu a tag, e não ao do componente. Slots com escopo não existem.

Um trecho da página some sem erro nenhum

Se o trecho que sumiu vem logo depois de uma tag de componente, olhe o fechamento dela. O HTML não aceita fechamento automático fora das tags conhecidas: <VInput ... /> não fecha nada, e o navegador coloca todo o resto do bloco dentro do componente. Escreva sempre <VInput ...></VInput>.

A interpolação apareceu crua na tela

Duas causas. A primeira: o trecho está dentro de <pre>, <code>, <script>, <style>, <textarea> ou de um v-ignore, onde a varredura não entra de propósito.

A segunda: a expressão tem chaves dentro, como { $t('itens', { n: total }) }. A varredura fecha na primeira chave. Nesses casos, use v-text, que recebe a expressão inteira no atributo.

Detalhes conhecidos, com contorno

Estes dependem de correção
  • A confirmação aparece duas vezes. Acontece quando v-confirm está no mesmo elemento de um verbo HTTP ou de v-submit: as duas camadas leem o mesmo atributo. Deixe a pergunta em um lugar só, usando v-click com $http, ou $confirm(...) dentro da própria expressão.
  • A tradução some ao trocar de idioma. v-t-params é lido apenas na primeira renderização. Use a interpolação reativa: { $t('itens', { n: total }) }.
  • O gráfico volta a ser de linha quando os dados mudam. Os atributos v-chart-* são lidos na montagem. Com dados reativos, declare tudo no objeto: v-chart="{ type: 'bar', data: vendas }".
  • Os textos extras do v-confirm, como v-confirm-title, só funcionam com V.config.cleanAttributes = false.

As ferramentas

Quando o sintoma não está nesta lista, a página do inspetor de reatividade mostra como ver os escopos, os efeitos e as requisições acontecendo — e como instalar um tratador global de erros para o que escapa em produção. 

<div v-data="{ n: 0 }">
  <button @click="n++; $log('n agora é', n, 'escopo:', $data)">
    Somar e registrar no console
  </button>
  <p>{ n }</p>
</div>
