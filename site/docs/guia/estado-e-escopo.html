Fundamentos

Estado e escopo com v-data

Toda página interativa precisa lembrar de alguma coisa: se o menu está aberto, o que foi digitado, quais itens estão na lista. Na Voodoo isso mora em um v-data, e o pedaço de HTML que o declara é o dono daquele estado.

O básico

O valor do v-data é um objeto. Cada chave vira uma variável disponível naquele elemento e em tudo que estiver dentro dele. 

<div v-data="{ aberto: false, itens: ['pão', 'leite'] }">
  <button @click="aberto = !aberto">Alternar menu</button>
  <p v-show="aberto">{ itens.length } itens na lista</p>
</div>

Não existe declaração em outro arquivo, não existe setState, não existe passo de registro. O objeto do atributo é o estado.

Escopo, e o que um escopo enxerga do outro

Cada v-data cria um escopo. Escopos aninham, e o de dentro enxerga o de fora. 

<div v-data="{ tema: 'escuro' }">
  <div v-data="{ aberto: false }">
    <button @click="aberto = !aberto">Tema atual: { tema }</button>
    <p v-show="aberto">O botão enxerga tema e aberto ao mesmo tempo.</p>
  </div>
</div>

Duas regras evitam praticamente toda a surpresa daqui:

  • A leitura sobe a cadeia. A Voodoo procura a variável no v-data mais próximo, depois nos ancestrais, depois na raiz.
  • A escrita vai para quem já tem a chave. Escrever em tema de dentro do escopo interno altera o tema do escopo externo, e não uma cópia. Uma chave que não existe em lugar nenhum é criada no escopo local.
O erro clássico

Escrever @click="abrto = true" com um erro de digitação não estoura nada: a biblioteca cria a chave abrto no escopo local, e o v-show="aberto" continua parado, sem nenhuma mensagem. Se um valor não reage, comece conferindo o nome. Ligar data-devtools na tag do script transforma esses casos em aviso no console.

O que é reativo

Tudo que está dentro de um v-data vira um objeto observado, em profundidade. Trocar um valor, empurrar um item em uma lista, apagar uma chave: qualquer uma dessas coisas reexecuta apenas os pedaços da página que leram aquele valor. 

<div v-data="{ carrinho: [] }">
  <button @click="carrinho.push({ nome: 'Caneca', preco: 39 })">Adicionar</button>
  <button @click="carrinho.pop()">Remover</button>
  <p>{ carrinho.length } itens, total { carrinho.reduce((s, i) => s + i.preco, 0) }</p>
</div>

O parágrafo se atualiza porque leu carrinho.length. Um outro parágrafo que não leia nada de carrinho nem chega a ser visitado — é isso que a documentação quer dizer com atualização granular.

Métodos de array funcionam todos

push, pop, splice, sort, reverse, shift e unshift disparam a atualização. Atribuir por índice (lista[2] = 'x') e mexer em lista.length também. Não existe a limitação clássica de precisar trocar o array inteiro.

Funções dentro do estado

Uma chave do v-data pode ser uma função. Dentro dela, this é o próprio escopo, o que evita repetir expressões longas em vários atributos. 

<div v-data="{
  itens: [{ nome: 'Caneca', preco: 39 }, { nome: 'Camiseta', preco: 89 }],
  total() { return this.itens.reduce((s, i) => s + i.preco, 0) },
  adicionar() { this.itens.push({ nome: 'Novo', preco: 10 }) }
}">
  <button @click="adicionar()">Adicionar item</button>
  <p>{ itens.length } itens, R$ { total() }</p>
</div>

Rodando algo assim que o escopo nasce

O v-init executa uma expressão uma única vez, logo depois que o escopo é criado. Serve para preparar valores derivados, disparar uma primeira busca ou ler algo do documento. 

<div v-data="{ agora: '' }" v-init="agora = new Date().toLocaleTimeString()">
  <p>A página abriu às { agora }.</p>
</div>

Lendo e escrevendo o escopo pelo JavaScript

Às vezes o valor precisa mudar a partir de código solto — um callback de outra biblioteca, um setInterval, um evento do próprio navegador. V.getScope(elemento) devolve o escopo daquele nó, e .data é o objeto reativo: escrever nele atualiza a tela do mesmo jeito que uma directive. 

<div id="painel" v-data="{ online: true }">
  <p>{ online ? 'Conectado' : 'Sem conexão' }</p>
</div>

<script>
  const painel = V.getScope(document.getElementById('painel')).data;
  addEventListener('offline', () => { painel.online = false; });
  addEventListener('online',  () => { painel.online = true; });
</script>

V.getScope(no) devolve o escopo declarado naquele nó, ou undefined se ele não declarou nenhum. V.findScope(no) sobe pelos ancestrais até achar um, e cai no escopo raiz quando não encontra. O escopo raiz é V.scope, e V.data({ ... }) escreve nele valores visíveis para a página inteira.

Existe caminho pronto para isso

Para esse caso específico, as directives v-online e v-offline já fazem o trabalho sem JavaScript. O exemplo vale como forma de alcançar o escopo de fora, que é o que interessa aqui.
