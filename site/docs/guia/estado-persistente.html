Componentes e estado

Estado que persiste, sincroniza e desfaz

Três comportamentos que normalmente custam bastante código: sobreviver ao recarregar, andar junto com as outras abas abertas, e ter desfazer. Cada um é um atributo.

v-persist

Guarda o escopo de um v-data no localStorage e restaura no próximo carregamento: 

<div v-data="{ tema: 'escuro', rascunho: '' }" v-persist="editor-de-exemplo">
  <textarea v-model="rascunho" placeholder="Escreva e recarregue a página"></textarea>
  <p>{ rascunho.length } caracteres guardados</p>
</div>

Os detalhes que importam:

  • a chave vira voodoo:persist:editor-de-exemplo;
  • sem valor, a chave é derivada do caminho da página e da posição do elemento;
  • só as chaves que o estado atual declara são restauradas, então acrescentar um campo novo ao v-data não quebra o que já estava salvo;
  • funções, valores começando com cifrão e estruturas circulares ficam de fora;
  • a gravação tem debounce de 120 ms;
  • ao remover o elemento, a gravação pendente é aplicada e o observador é encerrado.
O que não guardar

localStorage é legível por qualquer script da mesma origem e sobrevive indefinidamente. Rascunho de texto, filtro de lista e preferência de tema são bons candidatos. Token, dado de cartão e informação pessoal, não.

v-sync

Mantém o escopo em sincronia com as outras abas abertas, ao vivo, usando BroadcastChannel: 

<div v-data="{ contador: 0 }" v-sync="painel">
  <button @click="contador++">{ contador }</button>
</div>

Abra a página em duas abas e clique: as duas mudam juntas. Sem valor, o nome do canal é derivado da posição do elemento. Em navegadores sem BroadcastChannel, a directive simplesmente não faz nada — a página continua funcionando, só não sincroniza.

Para sincronia entre abas e sobrevivência ao recarregar, combine as duas:

<div v-data="{ filtro: '' }" v-persist="lista" v-sync="lista"></div>

v-history, v-undo e v-redo

Desfazer e refazer para o escopo inteiro, não para um campo:

<div v-data="{ texto: '', cor: '#6d3bf5' }" v-history="50">
  <div class="linha">
    <input v-model="texto" placeholder="Escreva alguma coisa">
    <input type="color" v-model="cor">
  </div>
  <div class="linha">
    <button v-undo :disabled="!$history.canUndo">Desfazer</button>
    <button v-redo :disabled="!$history.canRedo">Refazer</button>
    <small>{ $history.size } estados guardados</small>
  </div>
  <div :style="{ background: cor, color: '#fff', padding: '.5rem', borderRadius: '6px' }">
    { texto || 'nada ainda' }
  </div>
</div>

O valor de v-history é o limite de instantâneos, com padrão 50. Um instantâneo é gravado 300 ms depois da última mudança — por isso digitar uma palavra inteira vira um passo, e não uma letra por passo. Escrever depois de desfazer descarta o futuro, como em qualquer editor.

Campo de $historyO que é
canUndo, canRedoBooleanos reativos
sizeQuantidade de estados guardados
undo(), redo()Navega no histórico
clear()Apaga tudo e recomeça do estado atual

v-undo e v-redo ligam o clique ao controlador mais próximo na árvore, então os botões podem estar em qualquer lugar dentro do escopo com histórico.

v-storage, para um campo só

Quando não existe escopo nenhum e você só quer que aquele campo não perca o que foi escrito: 

<input v-storage="rascunho-do-comentario" placeholder="Escreva e recarregue">

O valor é gravado a cada tecla na chave voodoo:field:<nome> e restaurado ao carregar.

Armazenamento por JavaScript

V.storage.set('usuario', { id: 1, nome: 'Ana' });   // localStorage com JSON
V.storage.get('usuario', {});                       // com valor padrão
V.storage.remove('usuario');
V.storage.has('usuario');
V.storage.keys();
V.storage.clear();

V.session.set('passo', 2);                          // sessionStorage, mesma API

V.cookie.set('token', 'abc', { expires: 7, sameSite: 'Lax', secure: true });
V.cookie.get('token');
V.cookie.remove('token');

V.cache.set('produtos', lista, 60000);              // memória, com expiração
await V.cache.remember('cep:01001000', 3600000, () => V.http.get('/api/cep/01001000'));

V.url.get('pagina');                                // query string
V.url.set('pagina', 2);                             // sem recarregar
V.url.merge({ ordem: 'nome', pagina: 1 });
V.url.all();

Todas as leituras e escritas são seguras: em modo privado, com cota cheia ou fora do navegador, as chamadas não lançam erro — devolvem o valor padrão e seguem.

Dentro do HTML, cada um tem a magia correspondente: $storage, $session, $cookie, $cache e $url. 

<div v-data="{ vista: false }" v-init="vista = $storage.get('dica-vista', false)">
  <p v-show="!vista">
    Dica importante que aparece uma vez só.
    <button @click="vista = true; $storage.set('dica-vista', true)">
      Não mostrar de novo
    </button>
  </p>
  <button @click="vista = false; $storage.remove('dica-vista')">Mostrar de novo</button>
</div>
Leitura de armazenamento não é reativa

$storage.get(...) lê o valor na hora em que a expressão roda, e nada avisa a tela quando ele muda depois. Um v-show="!$storage.get('dica-vista')" continuaria visível mesmo depois da gravação. Por isso o exemplo guarda a resposta em uma variável do escopo, que é reativa, e usa o armazenamento só para lembrar entre uma visita e outra. Quando o valor precisa ser reativo e persistente, o caminho mais curto é um store com persist, ou o v-persist do começo desta página.
