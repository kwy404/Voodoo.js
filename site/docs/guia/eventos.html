Fundamentals

Events and modifiers

The user clicks, types, submits. Something has to happen. All of the event listening fits in one attribute, and the modifiers hand you for free what normally turns into support code: preventDefault, stopPropagation, click-outside, waiting for typing to stop.

Three spellings, the same result

<div v-data="{ n: 0 }">
  <button @click="n++">Add</button>
  <button v-on:click="n = 0">Reset</button>
  <button v-click="n--">Subtract</button>
  <p>{ n }</p>
</div>

@event is the shortest, v-on:event is the full one, and v-click, v-input, v-keyup and other shorthands exist for anyone who prefers a single name per line. Pick one and keep it across the project.

Modifiers

After the event name, a dot turns on common behaviours: 

<form @submit.prevent="save()">Does not reload the page</form>
<div class="overlay" @click.self="close()">Only a click on the overlay itself counts</div>
<button @click.once="start()">Runs once and switches off</button>
<div @keydown.escape.window="close()">Listens on the whole window</div>
<div @click.outside="closeMenu()">A click anywhere outside here</div>
ModifierWhat it does
.preventpreventDefault() before running the expression
.stopstopPropagation(), the event does not bubble
.selfOnly fires when the target is the element itself
.onceRuns once and removes the listener
.captureListens in the capture phase
.passiveMarks the listener as passive, useful for scroll and touch
.windowInstalls the listener on window
.documentInstalls the listener on document
.outsideFires on clicks outside the element
.debounceWaits for the user to stop before running
.throttleLimits it to one run per interval
 
<div v-data="{ text: '', times: 0 }">
  <input v-model="text" @input.debounce="times++" v-debounce="500">
  <p>Typed: { text }</p>
  <p>Fired { times } times, counting half a second of silence.</p>
</div>

Keys

<div v-data="{ last: 'nothing yet' }">
  <input placeholder="Enter, Esc or Ctrl+Enter"
         @keyup.enter="last = 'Enter'"
         @keydown.esc="last = 'Esc'"
         @keydown.ctrl.enter="last = 'Ctrl+Enter'">
  <p>Last key recognized: { last }</p>
</div>

Accepted names: .enter, .esc or .escape, .space, .tab, .delete, .backspace, .up, .down, .left, .right, any letter from .a to .z and any digit from .0 to .9. The system keys are .ctrl, .shift, .alt and .meta, and they combine with the rest in the same spelling. 

<div @keydown.meta.k.window.prevent="openSearch()"></div>

Events the browser does not have

Some behaviours turn up all the time in interfaces and do not exist as a native event. Voodoo offers them in the same shape as the others: 

<button @hold.2s="deleteEverything()">Hold for two seconds to delete</button>
<div @visible="loadMore()">Fires when it enters the visible area</div>
<div @swipeleft="next()" @swiperight="previous()">Swipe gestures</div>
<button v-hotkey="ctrl+k" @click="openPalette()">A global keyboard shortcut</button>

And some more readable aliases for events that already exist: @hover for mouseenter, @unhover for mouseleave, @tap for click, @press for pointerdown, @release for pointerup, @rightclick for contextmenu and @type for input. 

<div v-data="{ state: 'idle' }">
  <button @hold.1s="state = 'held for a second!'"
          @hover="state = 'moused over'"
          @unhover="state = 'left'">
    Hover, or hold the click
  </button>
  <p>{ state }</p>
</div>

Inside the handler

Three variables are always available in an event expression: 

<input @input="search = $event.target.value">
<button @click="$el.classList.add('clicked')">I use the element itself</button>
<section @filter="apply($detail)">I receive the detail of a custom event</section>

$event is the event, $el is the element and $detail is the detail of a CustomEvent.

Emitting events of your own

$dispatch emits a CustomEvent that bubbles up the tree, which lets one stretch of the page tell another without the two sharing state. 

<div v-data="{ received: '' }" @product-picked="received = $detail.name">
  <button @click="$dispatch('product-picked', { name: 'Mug' })">Pick the mug</button>
  <button @click="$dispatch('product-picked', { name: 'Shirt' })">Pick the shirt</button>
  <p>Picked: { received || 'nothing' }</p>
</div>

Automatic cleanup

You do not have to remove anything

Every listener installed by a directive is removed on its own when the element leaves the DOM, including the ones registered on window or document by the .window and .document modifiers. A v-if that closes takes everything that was listening inside it along.
