Data and forms

Forms that validate and submit themselves

An ordinary sign-up form needs validation, an error message per field, a mask, AJAX submission, a success message and handling for the error the server sends back. It tends to be the dullest stretch of any page, and it is what Voodoo settles with the most attributes per line.

The whole form

<form v-submit="/api/users"
      v-method="POST"
      v-validate
      v-toast-success="User created!"
      v-toast-error="Could not create the user."
      v-reset-success
      v-redirect="/users">

  <input name="name" v-required v-minlength="3">
  <input name="email" type="email" v-required v-email>
  <input name="cpf" v-mask="cpf" v-cpf>
  <input name="phone" v-mask="phone" v-phone>
  <input name="password" type="password" v-strong-password>
  <input name="password2" type="password" v-match="password">

  <button type="submit" :disabled="$form.loading">
    { $form.loading ? 'Sending...' : 'Save' }
  </button>
</form>

Without one line of JavaScript: it validates, shows the error under each field, submits over AJAX, shows the message, clears the form and redirects.

The validation, working

Validation does not depend on a server, so this block really runs. Write an invalid email, any old CPF, and leave the field with Tab: 

<form v-validate>
  <div class="linha"><input name="name" placeholder="Name" v-required v-minlength="3"></div>
  <div class="linha"><input name="email" placeholder="Email" v-required v-email></div>
  <div class="linha"><input name="cpf" placeholder="CPF" v-mask="cpf" v-cpf></div>
  <div class="linha"><input name="age" placeholder="Age" v-validate-between="18,120"></div>
</form>

The failing field gets the class v-invalid and aria-invalid="true", and the message goes in right after it with role="alert" and aria-describedby tying the two together. v-validate switches the browser's native validation off and takes over, so that the look and the wording are yours, the same in every browser.

When each check happens

On its own, v-validate checks field by field: when the field loses focus, when it changes, and on every keystroke once it has failed already. The check of the whole form, before submitting, is done by v-submit — it is the one that holds the submission back, marks every failing field at once and moves the focus to the first of them. A form that handles submission itself, with @submit.prevent, has to call V.validateForm($el) if it wants that final check.

The state of the form

Every form with v-submit publishes the variable $form to whatever is inside it: 

<form v-submit="/api/contact">
  <input name="email" v-required v-email>

  <p v-show="$form.errors.email">{ $form.errors.email }</p>
  <p v-show="$form.success">{ $form.message || 'We got your message.' }</p>

  <button :disabled="$form.loading">Send</button>
</form>
Field of $formWhat it holds
loadingTrue while the request is in flight
savingTrue during an automatic save
successTrue after a successful submission
errorsA map of field to message
messageThe general message returned by the server
dataThe response body
statusThe HTTP status of the response
dirtyTrue once any field has been changed
progressUpload progress, from 0 to 100

Errors coming from the server

A 422 response, or any response carrying a map of errors, is handed back out to the right fields. The three shapes below are understood with no configuration: 

{ "errors": { "email": "Already registered" } }
{ "email": ["Already registered"] }
{ "message": "Invalid data", "errors": { "cpf": "Invalid" } }

Messages with no matching field become a summary at the top. The focus goes to the first field with a problem, which avoids the classic form that fails on a field off screen.

The available rules

As a short attribute: v-required, v-email, v-url, v-number, v-integer, v-minlength, v-maxlength, v-min, v-max, v-match, v-regex, v-cpf, v-cnpj, v-cep, v-phone, v-date, v-accepted and v-strong-password.

In the long form v-validate-<name>, all of the above plus decimal, alpha, alphanumeric, between, same, different, in, notin, after, before, creditcard and unique, which is asynchronous and asks a URL. 

<input v-validate-between="10,100">
<input v-date v-validate-before="today">
<input name="email" v-validate-unique="/api/check-email">

CPF and CNPJ really do check the verification digits, and a card goes through Luhn — it is not just counting characters. The full list, with the default wording of each message, is in the validation reference.

Your own message and your own rule

<input v-cpf v-error-message="This CPF does not check out.">
<input v-required v-error-target="#name-error">
V.validator('even', (value) => Number(value) % 2 === 0, 'Enter an even number.');
<input v-validate-even>

Registering a rule automatically creates the directive v-validate-even. It is the same road for business rules: a CNPJ that has to be on a list, a coupon that is only valid on certain dates. 

<div>
  <script>
    V.validator('even', (v) => Number(v) % 2 === 0, 'Enter an even number.');
  </script>
  <form v-validate>
    <div class="linha"><input name="n" placeholder="An even number" v-validate-even></div>
  </form>
</div>

Files, automatic drafts and a guard against leaving

<input type="file" name="attachment" v-upload="/api/upload" v-progress="#bar">

<div v-dropzone="/api/upload" v-field="attachments" accept="image/*" multiple>
  Drag images here
</div>

<form v-autosave="/api/drafts/7" v-method="PUT" v-guard="You have unsaved changes.">
  <textarea name="body"></textarea>
</form>
  • v-upload sends the file as soon as it is chosen, with progress in v-progress.
  • v-dropzone accepts dragged files and keeps the result in the field named by v-field.
  • v-autosave saves the draft while the person writes.
  • v-guard warns before leaving the page with pending changes.

A form with no server

Not every form submits to an API. When the destination is the page itself, use @submit.prevent and handle it in state — validation keeps working exactly the same way: 

<div v-data="{ items: [], text: '' }">
  <form v-validate @submit.prevent="items.push(text); text = ''">
    <div class="linha">
      <input name="text" v-model="text" v-required v-minlength="3" placeholder="New task">
      <button type="submit">Add</button>
    </div>
  </form>
  <ul><li v-for="(t, i) in items">{ t }</li></ul>
</div>
