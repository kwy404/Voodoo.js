Fundamentals

Hooks

useState, useEffect, useMemo, useRef and useContext, written straight into HTML attributes. They are a surface over primitives the library already had, so someone arriving from React can write what they already know and have it mean the right thing here.

useState

Holds a value and re-renders whatever reads it. It returns a ref, and reactive objects unwrap refs on read, so inside v-data it behaves as a plain value: no .value, and no setter function to thread around. 

<div v-data="{ count: useState(0) }">
  <p>Você clicou {count} vezes</p>
  <button @click="count++">clicar</button>
  <button @click="count = 0">zerar</button>
</div>

count++ rather than setCount(count + 1). The assignment is tracked by the same Proxy that tracks everything else, so there is no second way to write state.

useEffect

Runs a side effect and re-runs it when what it depends on changes. Returning a function from the body registers cleanup, called before the next run and again when the element is removed. 

<div v-data="{ segundos: useState(0) }"
     v-init="useEffect(() => {
       const id = setInterval(() => segundos++, 1000);
       return () => clearInterval(id);
     }, [])">
  <p>{segundos}s desde que a página abriu</p>
</div>

The empty array means once, exactly as in React. The returned clearInterval is what keeps the timer from outliving the element.

The dependency array is optional

This is the one place the hooks here are deliberately not React. Voodoo tracks reads through a Proxy, so with no array an effect re-runs when something it actually read changes. You do not have to list dependencies for correctness: the array is there for when you want to narrow it. 

<div v-data="{ nome: useState('Ana'), idade: useState(30) }">
  <input v-model="nome">
  <button @click="idade++">envelhecer</button>

  <p v-effect="useEffect(() => console.log('nome mudou:', nome), [nome])"></p>
  <p v-effect="useEffect(() => console.log('qualquer um dos dois mudou'))"></p>
</div>

The first logs only when the name changes, because the array says so. The second has no array, reads nothing, and so never re-runs. Open the console and type in the field.

useMemo

Caches a computation. With no array it becomes a lazy computed: recomputed only when something it read changed, and not at all while nothing did. With an array it recomputes when that array changes. 

<div v-data="{
  itens: useState([2, 7, 1, 9, 4]),
  total: useMemo(() => itens.reduce((a, b) => a + b, 0)),
  maior: useMemo(() => Math.max(...itens))
}">
  <p>itens: {itens.join(', ')}</p>
  <p>soma: {total} · maior: {maior}</p>
  <button @click="itens.push(itens.length + 10)">adicionar</button>
</div>

useRef

A box that survives re-evaluation and that nothing subscribes to. Use it for a timer id, a previous value, a counter you do not want on screen, anything you want to keep without the page reacting when it changes. 

<div v-data="{ renders: useRef(0), n: useState(0) }">
  <p v-effect="renders.current++">n vale {n}</p>
  <button @click="n++">mudar n</button>
  <button @click="alert('efeitos rodaram ' + renders.current + ' vezes')">
    quantas vezes rodou?
  </button>
</div>

Changing renders.current renders nothing. That is the whole point of it, and it is why useRef is the one hook here that does not return a ref in the reactive sense.

useContext

Shared state, reachable from any component without threading it through the markup by hand. It is backed by the store registry, so useContext('sessao') and $store.sessao are the same object. 

<div v-data="{ s: useContext('sessao', { nome: 'Ana', tema: 'claro' }) }">
  <p>Componente A vê: {s.nome}</p>
  <input v-model="s.nome">
</div>

<hr>

<div v-data="{ s: useContext('sessao') }">
  <p>Componente B vê: {s.nome}</p>
  <button @click="s.nome = 'Bia'">mudar daqui</button>
</div>

Nothing is passed between the two. The second argument creates the store on first use; leaving it out just reads what is already there.

Together with JSX

Hooks and JSX regions are independent, and both work in an ordinary .html file with no build step. A memo feeding a list is the common pairing. 

<div v-data="{
  busca: useState(''),
  frutas: useState(['maçã', 'pera', 'uva', 'melancia']),
  filtradas: useMemo(() => frutas.filter(f => f.includes(busca)))
}">
  <input v-model="busca" placeholder="filtrar">

  <ul>
    {filtradas.map(fruta => (
      <li>{fruta}</li>
    ))}
  </ul>

  <p>{filtradas.length === 0 ? <b>nada encontrado</b> : <span>{filtradas.length} resultado(s)</span>}</p>
</div>

One rule worth knowing

Inside v-data, a key can read the keys written before it: 

<div v-data="{ n: useState(4), dobro: useMemo(() => n * 2) }">

That works because v-data is filled one key at a time into the scope it is defining, rather than being evaluated whole somewhere else and handed over afterwards. Order matters, and only backwards: a key cannot read one written below it.

The one shape that keeps the older behaviour is a v-data that is not a plain object literal: a spread, a computed key, or a call returning an object. There is no partial state to expose midway through those, so they are evaluated whole, in the parent scope, as before.

How these differ from React

Three differences, all deliberate, and all of them things the reactive model here makes possible rather than corners cut.

No rule of hooks. Slots are keyed per element in call order within one evaluation, and v-data and v-init each evaluate once per element. Calling a hook inside a branch does not shift anything, because the order does not come from a render pass you have to keep stable by hand.

No setter pair. useState returns the value, not a [value, setValue] tuple. Assignment is already tracked, so a setter would be a second way to do what = does.

Dependencies are optional. Covered above, and worth repeating: an omitted array is not a bug waiting to happen here. It means "work it out", and the Proxy does.

What they do not do

There is no useReducer, no useCallback and no useLayoutEffect. The first two have no job in a model with no re-render pass (a function written in an attribute is not recreated on every render, so there is nothing to memoise), and the third would need a render pass to be laid out before.

Custom hooks in the React sense, a plain function calling other hooks, are also not available from inside the markup, because expressions cannot declare functions that outlive the attribute they are written in. Use a store for logic shared between components.
