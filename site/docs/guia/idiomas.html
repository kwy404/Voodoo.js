Interface and effects

Languages

Reactive internationalization. Switching language does not reload the page: every piece of text that went through t() and every number, currency or date formatter updates itself, because they all read the same reactive state.

voodoo.full.min.js only

The languages module exists only in the full build.

Configuring

V.i18n({
  locale: 'en',
  fallback: 'en',
  messages: {
    en: {
      common: { save: 'Save', cancel: 'Cancel' },
      hello: 'Hello, {name}!',
      items: 'no items | {n} item | {n} items'
    },
    'pt-BR': {
      common: { save: 'Salvar', cancel: 'Cancelar' },
      hello: 'Olá, {name}!',
      items: 'nenhum item | {n} item | {n} itens'
    }
  }
});
OptionDefaultWhat it does
localeV.config.localeThe starting language
fallbackenThe language used when the key does not exist
messagesMessages per language
currencyV.config.currencyDefault currency for c()
persisttrueKeeps the chosen language in localStorage
detecttrueDetects the browser language when nothing was saved
loadPathA URL template for loading on demand, with {locale}

The order of preference is: the saved language, the one detected in the browser, the one declared in the option, and finally the fallback. The chosen one also goes to document.documentElement.lang, which keeps screen readers and the browser's hyphenation coherent.

Working

<div>
  <script>
    V.i18n({
      locale: 'en',
      persist: false,
      detect: false,
      messages: {
        en: {
          title: 'Cart',
          hello: 'Hello, {name}!',
          items: 'no items | {n} item | {n} items',
          common: { save: 'Save' }
        },
        'pt-BR': {
          title: 'Carrinho',
          hello: 'Olá, {name}!',
          items: 'nenhum item | {n} item | {n} itens',
          common: { save: 'Salvar' }
        }
      }
    });
  </script>

  <div v-data="{ howMany: 0 }">
    <div class="linha">
      <button v-locale="en">English</button>
      <button v-locale="pt-BR">Português</button>
      <button @click="howMany++">+1</button>
    </div>

    <h4 v-t="title"></h4>
    <p v-text="$t('hello', { name: 'Ann' })"></p>
    <p>{ $t('items', howMany) }</p>
    <p>{ $c(1234.5) } · { $d('2026-08-29') }</p>
    <p v-text="$n(0.75, { style: 'percent' })"></p>
    <button v-t="common.save"></button>
  </div>
</div>

Switch the language and notice that the numbers and the date change along with the text: they come out of the same Intl objects configured by the active language.

Messages

The tree takes nesting at any depth, and the key is read with dots:

{ common: { buttons: { save: 'Save' } } }   // t('common.buttons.save')
{ 'common.buttons.save': 'Save' }           // the flattened map works too

When the key exists nowhere, t() returns the key itself. That beats empty text on screen, and it makes what is missing easy to find.

v-t

<button v-t="common.save"></button>
<abbr v-t:title="common.hint">?</abbr>
<span v-t="'menu.' + section"></span>

With no argument, it translates the element's content. With an argument, it writes into the named attribute — which settles title, placeholder and aria-label.

Interpolation

<span>{ $t('hello', { name: user.name }) }</span>
<span v-t="hello" v-t-params="{ name: user.name }"></span>
A known detail

v-t-params is read only on the first render. If the text has to follow a language switch or a change in the values, use interpolation with $t, which is fully reactive.

Pluralization

The forms are separated by a vertical bar:

{
  items: 'no items | {n} item | {n} items',
  messages: '{n} message | {n} messages'
}
<span>{ $t('items', { n: cart.length }) }</span>
<span>{ $t('items', cart.length) }</span>     <!-- shorthand for the same case -->
  • Two forms follow the language's Intl.PluralRules category directly.
  • Three forms reserve the first for zero, which is the custom in English and in Portuguese.
  • Four or more use the official order of the CLDR categories, which covers languages with dual and paucal.

The count is read from n or from count.

Switching language

<button v-locale="en">English</button>
<button v-locale="pt-BR">Português</button>
<button v-locale="chosenLanguage">Switch</button>

The active button gets the class v-locale-active. From JavaScript, the same thing is V.locale('en'), and $locale returns the language in use inside any expression.

Formatters

Magic variableFormatsExample
$nA number{ $n(1234.5) } → 1,234.5
$cCurrency{ $c(1234.5) } → $1,234.50
$dA date{ $d(order.createdAt) } → 8/29/2026
$rtRelative time{ $rt(order.createdAt) } → 5 minutes ago

All of them take options: $n(0.75, { style: 'percent' }), $c(99, 'USD'), $d(date, 'long'). Because they read the active language, they update themselves when it changes.
