Interface and effects

Modal, tabs, menu, drawer, drag and drop

Everything on this page works by writing HTML alone. Not one line of JavaScript is needed for a dropdown menu, tabs, a side drawer, a tooltip, a command palette and the rest, and none of them gives up accessibility to manage it.

What comes along without you asking

Each piece takes care of ARIA roles, keyboard navigation, a visible focus ring, closing on Esc and prefers-reduced-motion. The CSS is injected on demand, only when the feature is used, and every colour comes out of the --v-* variables, so both themes already work.

Show and hide

<div>
  <button v-toggle="#details">See the details</button>
  <div id="details" style="display:none">
    This block appears and disappears, and the button gets aria-expanded by itself.
  </div>
</div>

With no selector, the target is the next sibling. The .instant modifier cuts the animation. The button receives aria-controls and aria-expanded, updated on every click, and fires voodoo:toggle with { target, open }.

Accordion and panels

<div v-accordion v-accordion-single>
  <div v-accordion-item="open">
    <h4>Delivery</h4>
    <div>We ship within two business days.</div>
  </div>
  <div v-accordion-item>
    <h4>Returns</h4>
    <div>You have 30 days to return it.</div>
  </div>
  <div v-accordion-item>
    <h4>Payment</h4>
    <div>Pix, bank slip and card in up to 12 instalments.</div>
  </div>
</div>

Each item needs two children: the first is the header, the last is the panel. v-accordion-single keeps only one open at a time, and v-accordion-item="open" starts open. The arrow keys move between the headers.

For a lone panel, with no group, there are v-collapse and v-collapse-toggle: 

<button v-collapse-toggle="#faq-1">What is Voodoo?</button>
<div id="faq-1" v-collapse>
  <p>The HTML-first JavaScript framework.</p>
</div>

Tabs

<div v-tabs>
  <div role="tablist">
    <button v-tab="profile">Profile</button>
    <button v-tab="security">Security</button>
    <button v-tab="billing">Billing</button>
  </div>

  <section v-tab-panel="profile"><p>Your name, photo and bio.</p></section>
  <section v-tab-panel="security"><p>Password and two-step verification.</p></section>
  <section v-tab-panel="billing"><p>Plan, card and invoices.</p></section>
</div>

The tab, tablist and tabpanel roles are applied, arrow navigation works on both axes, and the active tab gets the class v-active. Tabs inside tabs work, because each v-tab belongs to the nearest v-tabs.

To keep the chosen tab in the URL, without reloading:

<div v-tabs v-tabs-url="section">...</div>

Dropdown menu, popover and tooltip

<div>
  <button v-dropdown="#actions">Actions</button>
  <div id="actions" v-dropdown-menu>
    <button>Edit</button>
    <button>Duplicate</button>
    <button>Export</button>
  </div>

  <button v-tooltip="Deletes the record for good" v-tooltip-position="right">
    Delete
  </button>
</div>

In the menu, this happens on its own:

  • the menu becomes role="menu" and each clickable child becomes role="menuitem";
  • arrows navigate, Home and End go to the ends;
  • Esc closes it and hands the focus back to the trigger, and clicking outside closes it;
  • the menu is moved to the body while it is open, so no overflow: hidden clips it;
  • it flips to the opposite side when it does not fit, and never leaves the screen.

v-popover is the same with role="dialog" and the focus trapped inside the panel: use it when the content has fields or more than one interactive element. The tooltip shows on hover and on keyboard focus, disappears on Esc, and uses aria-describedby.

Side drawer

<div>
  <button v-drawer="#side-menu">Open the menu</button>

  <aside id="side-menu" v-drawer-content v-drawer-side="left">
    <h4>Navigation</h4>
    <p><a href="#">Dashboard</a></p>
    <p><a href="#">Orders</a></p>
    <button v-drawer-close>Close</button>
  </aside>
</div>

v-drawer-side accepts left, right (the default), top and bottom. Esc closes it, Tab cycles inside the panel, and the focus goes back to the trigger on close. v-offcanvas is an alias of v-drawer.

Modal

<div>
  <button v-modal="#sign-in">Sign in</button>

  <div id="sign-in" v-modal-content>
    <h4>Sign in</h4>
    <p><input placeholder="Email"></p>
    <button v-modal-close>Cancel</button>
  </div>
</div>

v-modal-content hides the block until a modal adopts it. The modifiers of v-modal are .close, which closes instead of opening, and .toggle, which alternates.

From JavaScript, with control over size, focus and the return value:

const control = V.modal.open('#login', { size: 'sm' });
await control.closed;      // resolves when the dialog has finished closing

V.modal.close('#login');
V.modal.closeAll();
V.modal.isOpen('#login');

alert, confirm and prompt

<div v-data="{ answer: '' }">
  <div class="linha">
    <button @click="$alert('The order went through.', { icon: 'success' })">
      Alert
    </button>
    <button @click="$confirm('Delete the order?', { danger: true })
                      .then(ok => answer = ok ? 'deleted' : 'backed out')">
      Confirm
    </button>
    <button @click="$prompt('What should we call you?', { required: true })
                      .then(v => answer = v || 'cancelled')">
      Prompt
    </button>
  </div>
  <p>Answer: { answer || 'nothing yet' }</p>
</div>

All three return a promise, and they exist in JavaScript too as V.alert, V.confirm and V.prompt. For buttons of your own, there is V.dialog({ title, description, buttons }).

v-confirm

It intercepts the click, asks the question and only lets the action through after a yes. It works alongside v-click, @click and links, because the guard runs in the capture phase, before any other listener. 

<button v-confirm="Really delete?" v-click="remove()">Delete</button>
<button v-confirm.danger="This action cannot be undone."
        v-click="deleteAccount()">Delete the account</button>
<a v-confirm="Sign out of your account?" href="/logout">Sign out</a>
A known detail

Do not combine v-confirm with v-get, v-post, v-put, v-patch, v-delete or v-submit on the same element: today the question shows up twice, because those directives read the same attribute as well. Prefer v-click with $http, or ask for the confirmation with $confirm(...) inside the expression itself.

Notifications

<div class="linha">
  <button @click="$toast.success('User saved!')">Success</button>
  <button @click="$toast.error('Could not save')">Error</button>
  <button @click="$toast.info('A new version is available')">Info</button>
</div>

In JavaScript, besides the shorthands per type there are V.toast.loading(), which returns a handle with update() and close(), and V.toast.promise(promise, { loading, success, error }), which follows an operation from start to finish. The positions run from top-right, the default, to bottom-center.

Command palette

<div v-data="{ done: '' }">
  <button v-command="mod+k">Search the commands</button>

  <button v-command-item="Go to the dashboard" v-command-hint="Ctrl+D"
          @click="done = 'dashboard'"></button>
  <button v-command-item="Create a new order" @click="done = 'order'"></button>
  <button v-command-item="Toggle the theme" v-theme-toggle></button>

  <p>Last command: { done || 'none' }</p>
</div>

The items are indexed the moment the palette opens, so elements created by v-for come in too. The search ignores accents and case; the arrows navigate, Enter runs the item by clicking the original element, and Esc closes.

Scrolling, focus and entering the viewport

<a href="#pricing" v-scroll-to v-scroll-offset="80">Pricing</a>
<button v-scroll-to="top">Back to the top</button>

<nav v-scrollspy v-scrollspy-class="active" v-scroll-offset="80">
  <a href="#about">About</a>
  <a href="#pricing">Pricing</a>
</nav>

<header v-sticky="0">...</header>

<input v-focus.select>
<div v-focus-trap="modalOpen">...</div>

<ul v-infinite-scroll="loadMore()" v-infinite-distance="400px">...</ul>
<img v-lazy-src="/photos/large.jpg" alt="A beach">

v-scroll-to respects prefers-reduced-motion and moves the focus to the section, which keeps keyboard navigation coherent. v-scrollspy marks the link of the visible section with the chosen class and with aria-current. v-sticky applies position: sticky and adds the class v-stuck when the element sticks.

Drag and drop

The system is built on pointer events. The HTML5 Drag and Drop API was left aside on purpose: it does not work well on touch, it does not let you customize the dragged image and it does not help with sortable lists. Here, mouse, pen, touch and keyboard all work. 

<div v-data="{ order: [] }">
  <ul v-sortable @voodoo:sorted="order = $detail.order">
    <li data-id="a">First</li>
    <li data-id="b">Second</li>
    <li data-id="c">Third</li>
  </ul>
  <p>Current order: { order.join(', ') || 'a, b, c' }</p>
</div>

The direct children become draggable items, and the key of each is its data-id, or its id, or its position. On drop, the list fires voodoo:sorted with item, oldIndex, newIndex, from, to and order.

For lists that trade items with each other, like a task board:

<div v-dnd-group="kanban">
  <ul v-sortable><li>To do</li></ul>
  <ul v-sortable><li>Doing</li></ul>
  <ul v-sortable><li>Done</li></ul>
</div>

A handle limits the drag to one part of the item: v-sortable-handle=".handle", or the selector directly in the value, v-sortable=".handle". And for dragging onto a drop area, with no reordering at all, there are v-draggable and v-droppable.
