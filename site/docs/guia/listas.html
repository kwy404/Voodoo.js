Fundamentos

Listas e por que a chave importa

Você tem uma lista e quer um elemento para cada item. O v-for faz isso, e o :key é o que separa uma lista que se comporta de uma lista que perde o foco do campo toda vez que alguém filtra.

O básico

<div v-data="{ produtos: [
  { id: 1, nome: 'Caneca', preco: 39 },
  { id: 2, nome: 'Camiseta', preco: 89 }
] }">
  <ul>
    <li v-for="p in produtos" :key="p.id">{ p.nome } — R$ { p.preco }</li>
  </ul>
  <button @click="produtos.push({ id: Date.now(), nome: 'Novo', preco: 10 })">
    Adicionar
  </button>
</div>

Todas as formas aceitas

v-for não se limita a arrays. in e of são equivalentes. 

<div v-data="{
  usuarios: [{ id: 1, nome: 'Ana' }, { id: 2, nome: 'Beto' }],
  configuracoes: { tema: 'escuro', idioma: 'pt-BR' }
}">
  <p>Com índice:</p>
  <ul><li v-for="(usuario, i) in usuarios" :key="usuario.id">{ i }: { usuario.nome }</li></ul>

  <p>Sobre um objeto:</p>
  <ul><li v-for="(valor, chave) in configuracoes">{ chave } = { valor }</li></ul>

  <p>Sobre um número:</p>
  <ul><li v-for="n in 3">Item { n }</li></ul>

  <p>Sobre um texto:</p>
  <ul><li v-for="letra in 'abc'">{ letra }</li></ul>
</div>

Arrays, números, textos, objetos, Map e Set funcionam. Sobre um número, a contagem começa em 1 — v-for="n in 3" dá 1, 2 e 3.

Para repetir um grupo de elementos sem um invólucro, o <template> vale aqui também: 

<dl>
  <template v-for="p in produtos" :key="p.id">
    <dt>{ p.nome }</dt>
    <dd>{ p.preco }</dd>
  </template>
</dl>

Por que a chave importa

O :key diz à Voodoo como reconhecer o mesmo item entre duas atualizações. Sem chave, a biblioteca só sabe a posição: se a lista é reordenada ou filtrada, ela reaproveita o elemento da posição 1 para o novo item da posição 1, seja ele qual for.

Na prática isso significa campo perdendo o foco, texto em edição sumindo e rolagem pulando. Compare as duas listas abaixo: digite em um dos campos e depois clique em embaralhar. 

<div v-data="{ tarefas: [
  { id: 1, texto: 'Comprar café' },
  { id: 2, texto: 'Responder e-mail' },
  { id: 3, texto: 'Pagar boleto' }
] }">
  <button @click="tarefas.reverse()">Inverter a ordem</button>

  <p><b>Com :key</b></p>
  <div v-for="t in tarefas" :key="t.id"><input v-model="t.texto"></div>

  <p><b>Sem :key</b></p>
  <div v-for="t in tarefas"><input v-model="t.texto"></div>
</div>
Regra prática

Sempre que a lista puder ser reordenada, filtrada ou ter itens removidos do meio, coloque :key. A chave precisa ser estável e única na lista: o id do banco serve; o índice da posição, não — ele muda junto com a ordem, que é justamente o problema que a chave deveria resolver.

Filtrando e ordenando

Não existe filtro embutido na directive: a expressão do v-for aceita qualquer expressão que devolva uma coleção, então filter, slice e sort resolvem — com a ressalva de que sort altera o array original, então vale copiar antes. 

<div v-data="{
  busca: '',
  produtos: [
    { id: 1, nome: 'Caneca', preco: 39 },
    { id: 2, nome: 'Camiseta', preco: 89 },
    { id: 3, nome: 'Caderno', preco: 25 }
  ]
}">
  <input v-model="busca" placeholder="Filtrar...">

  <ul>
    <li v-for="p in produtos.filter(p => p.nome.toLowerCase().includes(busca.toLowerCase()))"
        :key="p.id">
      { p.nome } — R$ { p.preco }
    </li>
  </ul>

  <p v-if="!produtos.some(p => p.nome.toLowerCase().includes(busca.toLowerCase()))">
    Nada encontrado.
  </p>
</div>

Quando a expressão fica longa demais para caber no atributo, mova-a para uma função do v-data — o resultado é o mesmo e o HTML volta a ser legível.

v-for e v-if não convivem no mesmo elemento

Os dois assumem o controle daquele nó, então a biblioteca não tem como decidir quem manda. Coloque a condição em um filho, ou envolva a repetição em um <template>. 

<!-- não faça isso -->
<li v-for="n in lista" v-if="n % 2 === 0">{ n }</li>

<!-- faça isso -->
<li v-for="n in lista">
  <span v-if="n % 2 === 0">{ n }</span>
</li>

<!-- ou filtre na própria expressão -->
<li v-for="n in lista.filter(n => n % 2 === 0)">{ n }</li>

O que existe dentro de cada item

Cada iteração cria um escopo próprio. Dentro dele valem a variável do item, o índice quando declarado, e tudo que os escopos de fora oferecem. As variáveis mágicas continuam disponíveis, $el apontando para o elemento daquela iteração. 

<div v-data="{ etiqueta: 'Produto', itens: ['Caneca', 'Camiseta'] }">
  <ul>
    <li v-for="(item, i) in itens">
      { etiqueta } { i + 1 }: { item }
      <button @click="itens.splice(i, 1)">remover</button>
    </li>
  </ul>
  <p v-if="!itens.length">A lista está vazia.</p>
</div>

O limite que vale conhecer

O v-for renderiza todos os itens da fonte: não existe virtualização. Para listas de algumas centenas de linhas isso é irrelevante. Para dezenas de milhares atualizando ao mesmo tempo, pagine, use rolagem infinita com v-infinite-scroll, ou escolha uma ferramenta que virtualize. A página de desempenho mede o custo real com números.
