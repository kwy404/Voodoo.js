Data and forms

Field masks

Typing masks that keep the cursor where it was, including when the user edits the middle of the text or deletes a separator. That is the detail separating a good mask from the kind everybody switches off after two days.

The basics

<div v-data="{}">
  <div class="linha"><input v-mask="cpf" placeholder="CPF"></div>
  <div class="linha"><input v-mask="phone" placeholder="Phone"></div>
  <div class="linha"><input v-mask="cep" placeholder="CEP"></div>
  <div class="linha"><input v-mask="(99) 99999-9999" placeholder="A pattern of your own"></div>
  <div class="linha"><input v-mask-currency placeholder="Currency"></div>
</div>

Try editing the middle of a number you already typed: the cursor stays where it was. Backspace over a dot: the digit before it is removed, not just the separator.

A mask and a validation are separate things, and they go together well: the mask formats while you type, the rule checks at the end. 

<input v-mask="cpf" v-cpf>
<input v-mask="cpfcnpj" placeholder="CPF or CNPJ">
<input v-mask="phone" v-phone>

A mask as a character pattern

When the value is not the name of a known mask, it is read as a pattern: 

<input v-mask="(99) 99999-9999">
<input v-mask="AAA-9999">
<input v-mask="SSSS SSSS">
<input v-mask="\R\S 9999">
TokenAccepts
9A digit
AA letter, accents included
SA letter or a digit
*Any character
\Escapes the next character, making it literal

Any other character in the pattern goes in as a fixed separator and only shows up while there is still content after it — which is why the mask does not push empty parentheses into a field that is still blank.

v-model and the clean value

By default the state receives the formatted text. With .unmask (or .raw), it receives the clean value while the screen keeps showing the mask — which is almost always what the server wants to receive. 

<div v-data="{ form: { cpf: '', price: '' } }">
  <div class="linha"><input v-mask.unmask="cpf" v-model="form.cpf" placeholder="CPF"></div>
  <div class="linha"><input v-mask-currency.unmask v-model="form.price" placeholder="Price"></div>
  <p v-text="'Goes to the server: ' + JSON.stringify(form)"></p>
</div>

v-mask runs before v-model, so the state never sees a half-formatted value.

Currency and percentage

v-mask-currency types from right to left, like a calculator: 

<input v-mask-currency>                      <!-- R$ 1.234,56 -->
<input v-mask-currency="US$ ">               <!-- US$ 1.234,56 -->
<input v-mask-currency v-mask-decimals="0">  <!-- R$ 1.234 -->
<input v-mask-currency v-mask-suffix=" /mo">
<input v-mask-currency.plain>                <!-- 1.234,56, with no prefix -->
<input v-mask-currency.dot>                  <!-- 1,234.56, in the American style -->

Things to watch

A mask only on a textual field

v-mask needs an <input> or <textarea> of a textual type. Types like number, range, date and color do not accept a mask, because the browser already controls the value. Use type="text" with inputmode, which brings up the numeric keyboard on a phone without taking control of the field away: 

<input type="text" inputmode="numeric" v-mask="cpf">
<input type="text" inputmode="decimal" v-mask-currency>

A value that already arrives from the server in the value is formatted as soon as the directive mounts, so an edit screen opens with everything in place.

Creating masks

From a character pattern:

V.registerMask('caseNumber', '9999999-99.9999.9.99.9999');
V.registerMask('renavam', '99999999999');

From a function, for cases that change with the content:

V.registerMask('registration', (value) => {
  const digits = value.replace(/\D/g, '');
  return digits.length <= 9
    ? V.applyMask(digits, '999.999.999')
    : V.applyMask(digits, '999.999.999.999');
});
<div>
  <script>
    V.registerMask('caseNumber', '9999999-99.9999.9.99.9999');
  </script>
  <input v-mask="caseNumber" placeholder="Case number">
</div>

From JavaScript

V.mask('12345678901', 'cpf');        // '123.456.789-01'
V.applyMask('1234', '99-99');        // '12-34'
V.unmask('123.456.789-01');          // '12345678901'
V.unmask('R$ 1.234,56', 'currency'); // '1234.56'

V.mask.currency('123456');           // 'R$ 1.234,56'
V.mask.percent('1250');              // '12,50%'

The complete table for V.mask is in the mask reference.

How the cursor is handled

The implementation counts the significant characters before the cursor, reformats the text and puts the cursor back after the same number of significant characters. Three consequences follow, and they are the ones that matter: editing the middle of the text does not throw the cursor to the end; deleting over a separator removes the useful character before it; and numeric masks keep the cursor at the end, before the suffix.

The input's value property is replaced, so that reading input.value returns the clean value while .unmask is on, and writing to it always goes through the mask. On unmount, the original property is restored.
