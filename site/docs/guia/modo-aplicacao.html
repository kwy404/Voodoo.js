Começando

Os dois modos: atributos e createApp

A Voodoo.js tem dois jeitos de assumir uma página, e os dois valem. O primeiro liga atributos ao HTML que já existe. O segundo descreve a aplicação em JavaScript e monta em uma raiz, no mesmo formato do Vue. Você escolhe por página, e pode usar os dois na mesma.

Modo atributos, sobre o HTML que já existe

<div v-data="{ n: 0 }">
  <button @click="n++">Cliques: { n }</button>
</div>

É o modo padrão: você aponta a tag do script, escreve atributos, e a biblioteca percorre o documento. Serve bem a páginas geradas no servidor, onde o HTML já vem pronto e só falta comportamento.

Modo aplicação, com createApp

<div id="contador"></div>

<script>
  V.createApp({
    data: () => ({ n: 0 }),
    computed: { dobro() { return this.n * 2 } },
    methods: { somar() { this.n++ } },
    template: `
      <button @click="somar()">Cliques: { n }</button>
      <p>Dobro: { dobro }</p>
    `
  }).mount('#contador');
</script>

Aqui a aplicação inteira mora em JavaScript: estado, computados, métodos, watchers, ciclo de vida e o HTML do template. O container começa vazio e recebe o resultado. Quem vem do Vue vai reconhecer tudo, inclusive os nomes.

Componentes locais, provide e inject

<div id="painel"></div>

<script>
  V.createApp({
    provide: { usuario: 'Ana' },
    components: {
      'cartao-painel': {
        props: ['titulo'],
        template: '<article><b>{ titulo }</b> <slot></slot></article>'
      },
      'rodape-painel': {
        inject: ['usuario'],
        template: '<small>Logado como { usuario }</small>'
      }
    },
    template: `
      <cartao-painel titulo="Receita">R$ 128.400</cartao-painel>
      <rodape-painel></rodape-painel>
    `
  }).mount('#painel');
</script>

Os componentes declarados em components saem do registro quando a aplicação é desmontada, então duas aplicações na mesma página podem ter um cartao cada uma sem brigar por nome. provide e inject funcionam como no Vue: o valor desce pela árvore, e o componente pede pelo nome, com default quando ninguém forneceu.

O agendador próprio

Esta é a diferença que vale mais no dia a dia. A Voodoo não usa DOMContentLoaded nem document.readyState para decidir quando começar: ela tem o próprio laço, que pergunta se o que ela precisa já existe e parou de mudar.

Na prática, mount aceita um alvo que ainda não está na página:

<script>
  // O container ainda nem existe. A montagem espera por ele.
  const app = V.createApp({ template: '<p>montei quando deu</p>' });
  app.mount('#tela-2');

  // ...outro script, outro momento, e a aplicação monta sozinha.
</script>
SituaçãoVue e ReactVoodoo.js
Script no <head>, sem deferFalha: o container não existeMonta quando o container aparece
Container criado por outro scriptFalha, ou exige orquestraçãoMonta sozinho
Página já carregada faz tempoMonta na horaMonta na hora

As três funções do agendador estão publicadas: V.whenReady(fn), que espera o documento ter corpo e parar de crescer, V.whenElement(seletor, fn), que espera um elemento, e V.ready(fn?), que também devolve promessa. 

V.whenElement('#grafico', (el) => V.renderChart(el, { type: 'line', data: serie }));
await V.ready();

Os dois modos na mesma página

<div v-data="{ fora: 'atributos' }">
  <p>Este pedaço é o modo { fora }.</p>
</div>

<div id="parte-app"></div>

<script>
  V.createApp({
    data: () => ({ dentro: 'createApp' }),
    template: '<p>E este é o modo { dentro }.</p>'
  }).mount('#parte-app');
</script>

Os dois compartilham a mesma reatividade, os mesmos stores e as mesmas directives. Um $store criado em qualquer lugar aparece nos dois lados, o que faz da adoção uma escolha por tela, e não pelo projeto inteiro.

Qual usar

SituaçãoModo
Página gerada por Laravel, Rails, Django ou PHPAtributos
Um trecho interativo dentro de um site de conteúdoAtributos
Tela inteira montada no cliente, com muitos componentescreateApp
Você vem do Vue e quer o formato conhecidocreateApp
Precisa desmontar e remontar a interfacecreateApp, pelo unmount
O que não muda entre os dois

Directives, expressões, componentes, stores, HTTP declarativo, formulários, máscaras, interface, animações e gráficos são os mesmos. createApp muda de onde vem o HTML e quem manda na raiz, e nada mais.
