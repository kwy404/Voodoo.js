Fundamentos

Mostrando valores na tela

O valor já está no estado. Falta colocá-lo na página. Existem três formas, e a diferença entre elas cabe em uma frase: interpolação e v-text escapam o HTML sozinhos, v-html não escapa nada.

Interpolação

A forma mais curta é escrever a expressão entre chaves, direto no texto: 

<div v-data="{ usuario: { nome: 'Ana' }, total: 1234.5 }">
  <p>Bem-vinda, { usuario.nome }.</p>
  <p>Total: { total.toFixed(2) }</p>
  <p>{ total > 1000 ? 'Compra grande' : 'Compra normal' }</p>
</div>

A Voodoo usa chave simples: { variavel }. A forma dupla {{ variavel }}, do Vue, também funciona, para quem já tem o costume. As duas convivem no mesmo arquivo.

A expressão pode fazer conta, chamar método, comparar e encadear — é o mesmo subconjunto de JavaScript aceito em qualquer atributo, descrito na referência de expressões.

Onde a interpolação não acontece

Dentro de <pre>, <code>, <script>, <style> e <textarea> a varredura não entra. Assim você mostra exemplos de código na página sem que a biblioteca tente avaliar as chaves — é exatamente o que esta documentação faz.

Para desligar a varredura em qualquer outra subárvore, existe o v-ignore: 

<div v-ignore>
  Este bloco fica exatamente como está, chaves e tudo: { não avaliado }
</div>
Objeto dentro da expressão, e quebra de linha

As duas coisas funcionam: { $t('itens', { n: total }) } conta as chaves e acha o fechamento certo, e uma expressão longa pode ser quebrada em várias linhas. O critério é analisar: o que a biblioteca consegue ler como expressão vira valor, e o que não consegue continua sendo texto exatamente como você escreveu — um trecho de CSS colado no parágrafo, por exemplo, fica intacto.

v-text

Quando o texto inteiro do elemento vem do estado, v-text é mais direto e não depende de chaves: 

<div v-data="{ usuario: { nome: 'Ana' }, total: 1234.5 }">
  <p><span v-text="usuario.nome"></span></p>
  <p><span v-text="'Total: ' + total.toFixed(2)"></span></p>
</div>

v-text escreve texto. Se o valor tiver <b> dentro, aparece a palavra <b> na tela, e não um negrito. O conteúdo que estiver escrito no elemento é substituído — o que também serve como texto de espera, visível antes de a biblioteca iniciar.

v-html

Quando o valor é HTML de verdade e você confia na origem dele: 

<div v-data="{ conteudo: '<b>negrito</b> e <i>itálico</i>' }">
  <p v-html="conteudo"></p>
  <p v-text="conteudo"></p>
</div>

Os dois parágrafos recebem o mesmo valor. O primeiro mostra o negrito; o segundo mostra as tags escritas por extenso. Essa é a diferença inteira.

O HTML inserido é percorrido pela Voodoo, então ele pode trazer directives dentro e elas funcionam. Isso é poderoso e perigoso ao mesmo tempo.

Nunca com conteúdo de terceiros

Comentário de usuário, campo de formulário, resposta de API pública: nada disso entra em um v-html sem passar por uma limpeza antes. Como o HTML inserido é processado pela biblioteca, um texto malicioso não precisa nem de <script> para fazer estrago. A página de segurança detalha o modelo de ameaça e o que a biblioteca protege sozinha.

Formatando na hora de mostrar

Os utilitários de formatação estão disponíveis dentro das expressões, o que evita guardar no estado uma versão já formatada do mesmo dado: 

<div v-data="{ preco: 1234.5, quando: '2026-08-29T10:30:00' }">
  <p>Moeda: { $c(preco) }</p>
  <p>Moeda em dólar: { $c(preco, 'USD') }</p>
  <p>Número: { $n(preco) }</p>
  <p>Data: { $d(quando) }</p>
  <p>Tempo relativo: { $rt(quando) }</p>
</div>
Só no build completo

$n, $c, $d e $rt vêm com o módulo de idiomas, que existe apenas no voodoo.full.min.js. Nos outros dois arquivos existem V.formatCurrency, V.formatNumber e V.formatDate, que fazem o mesmo a partir do JavaScript e podem ser liberados dentro das expressões por V.config.globals.

A lista inteira está na referência de utilitários. O idioma e a moeda usados vêm de V.config.locale e V.config.currency.
