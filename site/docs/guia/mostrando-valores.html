Fundamentals

Showing values on screen

The value is already in the state. What is left is putting it on the page. There are three ways, and the difference between them fits in one sentence: interpolation and v-text escape the HTML for you, v-html escapes nothing.

Interpolation

The shortest form is to write the expression between braces, right in the text: 

<div v-data="{ user: { name: 'Ann' }, total: 1234.5 }">
  <p>Welcome, { user.name }.</p>
  <p>Total: { total.toFixed(2) }</p>
  <p>{ total > 1000 ? 'Large order' : 'Normal order' }</p>
</div>

Voodoo uses a single brace: { variable }. The double form {{ variable }}, from Vue, works too, for anyone already in the habit. The two live side by side in the same file.

The expression can do arithmetic, call a method, compare and chain — it is the same subset of JavaScript accepted in any attribute, described in the expression reference.

Where interpolation does not happen

Inside <pre>, <code>, <script>, <style> and <textarea> the sweep does not go in. That is how you show code examples on a page without the library trying to evaluate the braces — exactly what this documentation does.

To turn the sweep off in any other subtree, there is v-ignore: 

<div v-ignore>
  This block stays exactly as it is, braces and all: { not evaluated }
</div>
An object inside the expression, and line breaks

Both work: { $t('items', { n: total }) } counts the braces and finds the right closing one, and a long expression can be broken over several lines. The test is parsing: what the library can read as an expression becomes a value, and what it cannot stays as text exactly as you wrote it — a stretch of CSS pasted into the paragraph, for instance, comes through untouched.

v-text

When the entire text of the element comes from state, v-text is more direct and does not depend on braces: 

<div v-data="{ user: { name: 'Ann' }, total: 1234.5 }">
  <p><span v-text="user.name"></span></p>
  <p><span v-text="'Total: ' + total.toFixed(2)"></span></p>
</div>

v-text writes text. If the value has a <b> inside, the word <b> shows up on screen, not bold type. Whatever content is written in the element is replaced — which also makes it a placeholder, visible before the library starts.

v-html

When the value really is HTML and you trust where it came from: 

<div v-data="{ content: '<b>bold</b> and <i>italic</i>' }">
  <p v-html="content"></p>
  <p v-text="content"></p>
</div>

Both paragraphs get the same value. The first shows the bold type; the second shows the tags spelled out. That is the whole difference.

The inserted HTML is walked by Voodoo, so it can bring directives inside and they work. That is powerful and dangerous at the same time.

Never with third-party content

A user comment, a form field, the response of a public API: none of that goes into a v-html without being sanitized first. Because the inserted HTML is processed by the library, malicious text does not even need a <script> to do damage. The security page spells out the threat model and what the library guards against on its own.

Which one to use

SituationUse
A value in the middle of a sentenceInterpolation
The whole element is the valuev-text
The expression has braces inside itv-text
The value is trusted HTML, out of an editor of yoursv-html
The value came from outsideInterpolation or v-text, never v-html

Formatting at display time

The formatting utilities are available inside expressions, which saves you from keeping an already-formatted copy of the same data in state: 

<div v-data="{ price: 1234.5, when: '2026-08-29T10:30:00' }">
  <p>Currency: { $c(price) }</p>
  <p>Currency in dollars: { $c(price, 'USD') }</p>
  <p>Number: { $n(price) }</p>
  <p>Date: { $d(when) }</p>
  <p>Relative time: { $rt(when) }</p>
</div>
Full build only

$n, $c, $d and $rt come with the languages module, which exists only in voodoo.full.min.js. In the other two files there are V.formatCurrency, V.formatNumber and V.formatDate, which do the same from JavaScript and can be exposed inside expressions through V.config.globals.

The whole list is in the utilities reference. The locale and currency in use come from V.config.locale and V.config.currency.
