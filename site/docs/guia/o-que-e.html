O que é a Voodoo.js e quando usar

A Voodoo.js é um micro framework que descreve o comportamento da página em atributos do HTML. Ela foi feita para o meio do caminho: páginas que precisam de interatividade de verdade, mas que não justificam virar uma aplicação inteira em JavaScript.

O problema que ela resolve

Você quer uma lista que filtra, um formulário que valida e envia por AJAX, um modal e um aviso de sucesso. São quatro comportamentos comuns, e existem dois caminhos batidos para chegar lá.

Pelo caminho do jQuery, cada um vira um punhado de addEventListener, seletor e manipulação manual do DOM. Funciona, e depois de seis meses ninguém mais sabe qual trecho escreve em qual elemento.

Pelo caminho do Vue ou do React, cada um vira um componente — e junto vêm um passo de build, um bundler, um arquivo de configuração e uma pasta de dependências com centenas de megabytes. Para uma página. Que já era HTML.

A resposta da Voodoo é a terceira: os atributos descrevem o comportamento, e a biblioteca cuida do resto.

O que ela faz de diferente

O HTML fica limpo no final

Depois que uma directive é processada, o atributo v-* sai do documento. No inspetor do navegador você vê <button>Salvar</button>, e não <button v-click="salvar()" v-loading="#spin">. O comportamento continua funcionando porque o valor fica guardado no runtime.

Consequência prática

Nunca escreva CSS nem querySelectorAll apoiado em seletores como [v-tab]: no momento em que você procurar, o atributo já não existe. Use classes ou data-*, que permanecem. Quem precisa do comportamento antigo pode desligar isso em V.config.cleanAttributes.

Sem eval e sem new Function

As expressões dos atributos passam por um lexer, um parser Pratt e um interpretador de árvore escritos à mão. A biblioteca roda sob Content Security Policy restritiva, sem unsafe-eval. Isso também explica por que a expressão aceita menos coisas do que JavaScript inteiro: não existe function, não existe new, e os globais liberados são uma lista fechada.

Atualizações granulares, sem Virtual DOM

O rastreamento é por chave. Quando count muda, apenas os efeitos que leram count rodam de novo, e cada efeito escreve somente no nó que ele mesmo criou. Não existe árvore virtual para comparar, nem render de componente inteiro por causa de um número.

Interpolação com chave simples

{ variavel } é a forma padrão. {{ variavel }} também é aceita, para quem vem do Vue e tem o dedo viciado. 

<div v-data="{ n: 3 }">
  <p>Uma chave: { n * 2 }</p>
  <p>Duas chaves: {{ n * 2 }}</p>
</div>

Zero dependências em tempo de execução

Nada de React, Vue, lodash, jQuery ou Axios por baixo. Só APIs do navegador. O arquivo que você baixa é o projeto inteiro.

Para quem ela é

  • Painéis administrativos gerados no servidor com Laravel, Rails, Django, Spring ou PHP puro.
  • Landing pages e sites de conteúdo que precisam de um pouco de vida sem carregar um framework inteiro.
  • Protótipos, onde abrir um arquivo e ver o resultado vale mais do que qualquer arquitetura.
  • Times pequenos que não querem manter um pipeline de build só para mostrar uma tabela.
  • Projetos legados, onde a biblioteca convive com o código que já existe, porque ela nunca toma conta da página inteira.

Quando não usar

Vale dizer com clareza, porque escolher a ferramenta errada custa caro depois.

  • Aplicação muito grande, com dezenas de telas e um time grande. Componentes de arquivo único, roteamento aninhado e checagem de tipo em tempo de compilação são vantagens reais do Vue, do React e do Svelte nesse tamanho.
  • Você precisa de renderização no servidor com hidratação. A Voodoo roda no navegador. Ela convive bem com HTML vindo do servidor, mas não hidrata nada. Os módulos puros (reatividade, HTTP, utilitários) funcionam em Node.
  • Aplicativo móvel nativo. Não existe equivalente ao React Native aqui.
  • Listas com dezenas de milhares de linhas atualizando ao mesmo tempo. O v-for reaproveita elementos por chave, mas não faz virtualização.
  • Você quer o menor arquivo possível e só precisa de dois ou três comportamentos. O Alpine.js pode ser a escolha melhor.
  • Seu time já domina outro framework e o projeto já está em pé. Trocar por trocar não paga.

A leitura honesta: Alpine e HTMX são menores porque fazem menos. Vue e React têm ecossistema, ferramental e comunidade que a Voodoo não tem. A Voodoo entrega, em um arquivo, o conjunto que normalmente exige juntar cinco bibliotecas.

O que ainda não existe

Esta lista está aqui para que ninguém procure na documentação achando que já foi entregue.

Roadmap
  • Renderização no servidor e hidratação. Hoje a biblioteca só monta no navegador.
  • Virtualização de listas. O v-for renderiza todos os itens da fonte.
  • Extensão de navegador para as devtools. O inspetor xray roda dentro da própria página.
  • Rotas aninhadas. O v-router-view renderiza uma única saída, sem hierarquia.
  • Transições próprias por rota. O roteador usa a View Transitions API quando o navegador oferece, e nada além disso.
  • Componentes de data e de upload prontos. Existem VInput e VSelect, mas ainda não um seletor de data.
  • Tipos gerados para os templates. As expressões de atributo não têm checagem estática.

A página de problemas comuns lista, em separado, os detalhes conhecidos que dependem de correção e as formas de contornar cada um enquanto isso.
