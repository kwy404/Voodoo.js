Interface and effects

Router

A single-page application router, with no external dependency at all. Two modes: history, which uses the History API and clean URLs, and hash, which keeps the route after the # and works even when you open the file straight off disk.

voodoo.full.min.js only

The routing module exists only in the full build.

Configuring

V.router({
  mode: 'history',
  base: '/',
  routes: {
    '/': { component: 'home', title: 'Home' },
    '/users': { component: 'users', title: 'Users' },
    '/users/:id': { component: 'user-detail' },
    '/posts/:slug?': { view: '/partials/post.html' },
    '/admin': { component: 'admin', meta: { requiresLogin: true } },
    '/old': { redirect: '/new' },
    '*': { component: 'not-found', title: 'Page not found' }
  },
  beforeEach(to, from) {
    if (to.meta.requiresLogin && !isSignedIn()) return '/login';
    return true;
  },
  afterEach(to) {
    console.log('arrived at', to.path);
  }
});
<nav>
  <a v-link href="/">Home</a>
  <a v-link href="/users">Users</a>
</nav>

<main v-router-view>Loading...</main>

And working, in hash mode, which is what runs inside this frame:

<div>
  <script>
    V.component('page-home', { template: '<p>You are at the home page.</p>' });
    V.component('page-about', { template: '<p>A page about the project.</p>' });
    V.component('page-item', {
      template: '<p>Item number { $route.params.id }.</p>'
    });

    V.router({
      mode: 'hash',
      routes: {
        '/': { component: 'page-home', title: 'Home' },
        '/about': { component: 'page-about' },
        '/items/:id': { component: 'page-item' }
      }
    });
  </script>

  <nav class="linha">
    <a v-link href="#/">Home</a>
    <a v-link href="#/about">About</a>
    <a v-link href="#/items/42">Item 42</a>
  </nav>

  <main v-router-view>Loading...</main>
  <small>Current route: { $route.path }</small>
</div>

Options

OptionDefaultWhat it does
modehistoryhistory or hash
base/The common prefix of the routes in history mode
routesA map of pattern to definition
beforeEachA global guard before each navigation
afterEachA global hook after each navigation
linkActiveClassv-link-activeClass on a v-link when the route starts with its destination
linkExactActiveClassv-link-exact-activeClass when the route is exactly the destination
transitiontrueUses the View Transitions API when the screen changes
titleTemplate%sThe title template, with %s standing in for the route title
scrollBehaviorFine control of the scroll after navigating

The route definition

FieldWhat it does
componentThe name of a registered component, mounted inside the v-router-view
viewThe URL of remote HTML, fetched and inserted in its place
titleApplied to document.title on entering
nameThe route name, available in $route.name
metaFree-form data, available in $route.meta
redirectRedirects as soon as the route matches
beforeEnterA guard exclusive to this route, run before the global one

Patterns and specificity

/users          a fixed segment
/users/:id      a required parameter
/posts/:slug?   an optional parameter
*               a wildcard, taken when nothing else matches

The most specific route always wins: /users/new beats /users/:id, and * only comes in last. You do not have to worry about the order you declared them in.

$route

The state of the current route is reactive: any expression that reads $route updates itself. 

<h1>User { $route.params.id }</h1>
<p v-show="$route.query.new">Freshly created account</p>
<small>{ $route.path } · { $route.name }</small>
FieldWhat it is
pathThe path without the query and without the hash
fullPathThe complete path
paramsThe pattern parameters, such as { id: '42' }
queryThe query string turned into an object
hashThe anchor, without the #
nameThe name declared on the route
metaThe route metadata
matchedThe pattern that matched, or null

From JavaScript, the same object is in V.route.

v-router-view

<main v-router-view>Loading...</main>
<main v-router-view.no-transition></main>

A route with component mounts the registered component. A route with view fetches the remote HTML and inserts it with the directives already bound, keeping the result in cache. The element's original content comes back when no route matches — which is why it doubles as a loading state. The change uses the View Transitions API when the browser offers it.

v-link

<a v-link href="/users">Users</a>
<a v-link="'/users/' + user.id">Detail</a>
<a v-link.replace href="/login">Sign in</a>
<a v-link.no-scroll href="/list">No scrolling to the top</a>

Clicks with Ctrl, Command, Shift or Alt, clicks with anything but the main button, and links with target, with download or to another domain all keep the browser's native behaviour. Opening in a new tab keeps working the way the person expects.

Does not exist yet

Nested routes: v-router-view renders a single outlet, with no hierarchy of views. And there are no per-route transition classes of its own beyond what the View Transitions API offers.
