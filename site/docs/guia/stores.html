Componentes e estado

Estado global com stores

O carrinho aparece no cabeçalho e na lateral. Os dois precisam do mesmo dado, e eles não são vizinhos no HTML. Um v-data resolve dentro de um trecho; para a página inteira, use um store.

Criando um store

V.store('carrinho', {
  itens: [],
  total() {
    return this.itens.reduce((soma, item) => soma + item.preco, 0);
  },
  adicionar(produto) {
    this.itens.push(produto);
  },
  limpar() {
    this.itens = [];
  }
});

A partir daí ele existe em $store, em qualquer expressão da página, sem precisar ser passado para lugar nenhum: 

<div>
  <script>
    V.store('carrinho', {
      itens: [],
      total() { return this.itens.reduce((s, i) => s + i.preco, 0) },
      adicionar(p) { this.itens.push(p) },
      limpar() { this.itens = [] }
    });
  </script>

  <div>
    <button @click="$store.carrinho.adicionar({ nome: 'Caneca', preco: 39 })">
      Adicionar caneca
    </button>
    <button @click="$store.carrinho.limpar()">Limpar</button>
  </div>

  <p>Aqui em cima: { $store.carrinho.itens.length } itens</p>

  <div v-data="{ qualquerOutroEscopo: true }">
    <p>Em outro escopo, bem longe: R$ { $store.carrinho.total() }</p>
  </div>
</div>

Repare que o segundo parágrafo está dentro de outro v-data e mesmo assim enxerga o carrinho. Não existe herança entre eles: o store não pertence a escopo nenhum.

Método, e não getter

Para valores derivados use um método, como o total() acima. Uma propriedade declarada com get é resolvida uma única vez, na criação do store, e não acompanha as mudanças. É o erro mais comum desta página.

Persistência

V.store('preferencias', { tema: 'system', idioma: 'pt-BR' }, { persist: true });

O store é gravado no localStorage a cada mudança e restaurado no próximo carregamento. A chave padrão é voodoo:store:<nome>; passe um texto em persist para escolher outra, como { persist: 'app:prefs' }. Funções não são gravadas.

A API dos stores

V.store('carrinho');            // recupera o store existente
V.store('carrinho', { ... });   // cria, ou atualiza os valores mantendo a referência
V.stores;                       // objeto com todos os stores, o mesmo que $store
V.storeNames();                 // ['carrinho', 'preferencias']
V.removeStore('carrinho');      // remove e para a persistência
A ordem dos scripts não importa

Um store criado depois que a página carregou atualiza quem já estava na tela esperando por ele. Você não precisa garantir que o arquivo do store venha antes do HTML que o usa.

O nível intermediário: o escopo raiz

Entre o v-data de um bloco e um store nomeado existe o escopo raiz, que vale para a página toda sem virar um objeto com nome próprio: 

V.data({ usuario: null, versao: '2.1' });

Ele aparece como $root em qualquer expressão, e os identificadores soltos caem nele quando não existem em nenhum escopo acima. Serve bem para o que é único e não tem comportamento: o usuário logado, a versão do sistema, uma configuração vinda do servidor.

Barramento de eventos

Quando o que você precisa não é compartilhar um valor, e sim avisar que algo aconteceu: 

const off = V.on('pedido:criado', (pedido) => V.toast.success(`Pedido ${pedido.id} criado`));
V.once('app:pronto', () => console.log('só na primeira vez'));
V.emit('pedido:criado', { id: 42 });
off();                       // cancela uma assinatura
V.off('pedido:criado');      // cancela todas do evento

No HTML, o equivalente é $dispatch, que dispara um CustomEvent subindo pela árvore — bom para conversas entre partes próximas, enquanto o barramento serve para partes que não se conhecem.
