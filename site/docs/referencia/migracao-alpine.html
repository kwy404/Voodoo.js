Qualidade e migração

Migrando do Alpine

As duas partem da mesma ideia: comportamento declarado no HTML, sem passo de build. A conversão costuma ser quase mecânica. As diferenças reais aparecem no que a Voodoo traz junto, que no Alpine mora em plugins ou no seu próprio código.

Em v-model: .lazy, .number e .debounce existem nos dois — aqui o tempo do debounce vem do atributo v-debounce. .throttle não existe; .trim e .single, para arquivo, são novidades.

Variáveis mágicas

$el, $refs, $store, $watch, $dispatch, $nextTick, $root, $data e $event são iguais. $id vira V.uid(), e o $persist do plugin vira a directive v-persist.

Não existem no Alpine: $parent, $self, $detail, $http, $toast, $modal, $form, $storage, $cookie, $url, $cache, $screen, $network, $device, $theme, $clipboard, $route, $router, $t e $locale.

Store e dados globais

// Alpine
Alpine.store('carrinho', { itens: [], adicionar(p) { this.itens.push(p) } });

// Voodoo.js
V.store('carrinho', { itens: [], adicionar(p) { this.itens.push(p) } });
V.store('carrinho', { itens: [] }, { persist: true });   // persistência na criação

No HTML, os dois usam $store.carrinho.

// Alpine: Alpine.data
Alpine.data('dropdown', () => ({ aberto: false, alternar() { this.aberto = !this.aberto } }));

// Voodoo.js: um componente
V.component('dropdown', {
  state: () => ({ aberto: false }),
  methods: { alternar() { this.aberto = !this.aberto } }
});

Directives, magias e plugins

// Alpine
Alpine.directive('destaque', (el, { expression }, { evaluate }) => {
  el.style.background = evaluate(expression);
});
Alpine.magic('agora', () => new Date());
Alpine.plugin(meuPlugin);

// Voodoo.js
V.directive('destaque', (el, binding) => { el.style.background = binding.value });
V.magic('$agora', () => new Date());
V.use(meuPlugin, { opcao: true });

Inicialização

<script src="voodoo.min.js?v=0.6.2" data-manual></script>
<script>
  V.component('x', { /* ... */ });
  V.start();
</script>

Com a tag normal, V.start() é chamado sozinho — use data-manual quando quiser registrar tudo antes. O evento equivalente ao alpine:init é voodoo:ready, disparado depois da montagem.

Três diferenças que valem atenção

1. Interpolação com chave simples

<!-- Alpine -->
<span x-text="nome"></span>

<!-- Voodoo -->
<span>{ nome }</span>

2. Os atributos somem do HTML

Depois de processada, a directive sai do documento. Se você tem CSS ou scripts que dependem de seletores como [x-show], adapte para classes, ou desligue a limpeza com V.config.cleanAttributes = false.

3. v-if não precisa de template

<!-- Alpine -->
<template x-if="logado"><p>Bem-vindo</p></template>

<!-- Voodoo -->
<p v-if="logado">Bem-vindo</p>

O que você ganha na troca

  • requisições declarativas: v-get, v-post, v-resource, v-poll, v-search;
  • formulário AJAX completo com v-submit, validação, máscaras, upload e autosave;
  • interface: modal, gaveta, abas, dropdown, tooltip, acordeão, paleta de comandos;
  • notificações e diálogos com promessa;
  • arrastar e soltar acessível;
  • armazenamento, cookies, cache e query string;
  • no build completo: gráficos, animações com mola, roteador, idiomas e o inspetor.

O que você perde

  • o ecossistema de plugins do Alpine, que é maior e mais antigo;
  • x-modelable, que aqui vira props com emit;
  • a sintaxe de classes utilitárias direto no x-transition;
  • os modificadores .camel e .dot do x-bind;
  • e alguns kilobytes: o Alpine é menor porque faz menos.
Migração gradual

As duas bibliotecas usam prefixos diferentes, então convivem sem colisão na mesma página. Migre tela por tela, trocando x- por v-, e remova o Alpine quando não sobrar nenhum.
