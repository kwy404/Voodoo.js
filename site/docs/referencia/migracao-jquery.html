Qualidade e migração

Migrando do jQuery

A Voodoo.js tem uma coleção encadeável com a mesma ergonomia do jQuery, então boa parte do seu código continua parecido. A diferença de fundo é outra: no jQuery você manda o DOM mudar; aqui você descreve o estado, e o DOM acompanha. Dá para migrar aos poucos — as duas bibliotecas convivem na mesma página.

Seleção e percurso

jQueryVoodoo.js
$('#app')V('#app')
$('.item', contexto)V('.item', contexto)
$('<li>novo</li>')V('<li>novo</li>') ou V.fromHtml(...)
$(function () {})V(function () {}) ou V.ready(fn)
.find, .closest, .parent, .parentsiguais
.children, .siblings, .next, .previguais
.first, .last, .eq, .filter, .not, .has, .isiguais
.each, .get, .toArray, .lengthiguais

A coleção da Voodoo é iterável com for...of e com espalhamento:

for (const el of V('.item')) console.log(el);
const lista = [...V('.item')];

Conteúdo, classes e estilo

.text, .html, .val, .attr, .removeAttr, .prop, .data, .addClass, .removeClass, .toggleClass, .hasClass, .css, .width, .height, .offset, .position e .scrollTop têm o mesmo nome e o mesmo comportamento, inclusive nas formas com objeto.

Estrutura

.append, .prepend, .before, .after, .appendTo, .prependTo, .replaceWith, .wrap, .unwrap, .remove, .empty e .clone são iguais.

Uma diferença a favor

.remove() e .empty() também desmontam os efeitos reativos dos elementos removidos, o que evita vazamento — algo que no jQuery ficava por sua conta.

O salto: pare de mandar, comece a descrever

Um contador em jQuery:

let valor = 0;
$('#contador .mais').on('click', function () {
  valor++;
  $('#contador .valor').text(valor);
  $('#contador .menos').prop('disabled', valor === 0);
});
$('#contador .menos').on('click', function () {
  valor--;
  $('#contador .valor').text(valor);
  $('#contador .menos').prop('disabled', valor === 0);
});

O mesmo em Voodoo.js:

<div v-data="{ valor: 0 }">
  <button @click="valor--" :disabled="valor === 0">-</button>
  <span>{ valor }</span>
  <button @click="valor++">+</button>
</div>

A regra "o botão de menos fica desabilitado no zero" aparece uma vez, no lugar onde ela importa. No jQuery ela precisava ser repetida em todo lugar que mexia no valor, e esquecer uma repetição era o bug clássico.

Uma lista

// jQuery
function renderizar(itens) {
  const $ul = $('#lista').empty();
  itens.forEach((item) => {
    $ul.append('<li data-id="' + item.id + '">' + item.nome + ' <button class="x">remover</button></li>');
  });
}
$('#lista').on('click', '.x', function () {
  const id = $(this).closest('li').data('id');
  itens = itens.filter((i) => i.id !== id);
  renderizar(itens);
});
<ul v-data="{ itens: [{ id: 1, nome: 'Caneca' }, { id: 2, nome: 'Camiseta' }] }">
  <li v-for="item in itens" :key="item.id">
    { item.nome }
    <button @click="itens.splice(itens.indexOf(item), 1)">remover</button>
  </li>
</ul>

Não existe função de renderizar. Não existe delegação. Não existe data-id só para achar o item de volta.

Um formulário AJAX

// jQuery
$('#form').on('submit', function (e) {
  e.preventDefault();
  const $btn = $(this).find('button').prop('disabled', true).text('Enviando...');
  $.post('/api/contato', $(this).serialize())
    .done(() => { alert('Enviado!'); this.reset(); })
    .fail((xhr) => { $('#erro').text(xhr.responseJSON.message); })
    .always(() => { $btn.prop('disabled', false).text('Enviar'); });
});
<form v-submit="/api/contato" v-validate v-reset-success v-disable-loading
      v-toast-success="Enviado!">
  <input name="nome" v-required>
  <input name="email" type="email" v-required v-email>
  <button>{ $form.loading ? 'Enviando...' : 'Enviar' }</button>
</form>

Validação, estado de carregamento, erros por campo e notificação vêm juntos.

Plugins do jQuery

Um plugin que precisa de um elemento vira uma directive:

// jQuery
$('.data').datepicker({ format: 'dd/mm/yyyy' });

// Voodoo.js
V.directive('datepicker', {
  mounted(el, binding) {
    el.__picker = new SeuDatepicker(el, { format: binding.value || 'dd/mm/yyyy' });
  },
  unmounted(el) { el.__picker.destroy(); }
});
<input v-datepicker="'dd/mm/yyyy'">
Por onde começar a migração

Troque primeiro os trechos que mais sofrem com sincronização manual: listas que filtram, formulários e qualquer estado que aparece em dois lugares. O resto do código jQuery continua rodando ao lado, e você converte quando for mexer nele de qualquer jeito.
