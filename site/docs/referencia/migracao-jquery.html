Quality and migration

Migrating from jQuery

Voodoo.js has a chainable collection with the same ergonomics as jQuery, so much of your code stays recognizable. The underlying difference is elsewhere: in jQuery you tell the DOM to change; here you describe the state, and the DOM follows. You can migrate a bit at a time, the two libraries coexist on the same page.

Selection and traversal

jQueryVoodoo.js
$('#app')V('#app')
$('.item', context)V('.item', context)
$('<li>new</li>')V('<li>new</li>') or V.fromHtml(...)
$(function () {})V(function () {}) or V.ready(fn)
.find, .closest, .parent, .parentssame
.children, .siblings, .next, .prevsame
.first, .last, .eq, .filter, .not, .has, .issame
.each, .get, .toArray, .lengthsame

The Voodoo collection is iterable with for...of and with spreading:

for (const el of V('.item')) console.log(el);
const list = [...V('.item')];

Content, classes and style

.text, .html, .val, .attr, .removeAttr, .prop, .data, .addClass, .removeClass, .toggleClass, .hasClass, .css, .width, .height, .offset, .position and .scrollTop have the same name and the same behavior, including the object forms.

Structure

.append, .prepend, .before, .after, .appendTo, .prependTo, .replaceWith, .wrap, .unwrap, .remove, .empty and .clone are the same.

One difference in your favor

.remove() and .empty() also tear down the reactive effects of the removed elements, which avoids leaks, something that in jQuery was left to you.

Events

jQueryVoodoo.js
.on('click', fn)same
.on('click', '.button', fn)same, with delegation
.one('click', fn).once('click', fn)
.off('click'), .trigger('click')same
.trigger('my:event', data).emit('my:event', data)
.click().trigger('click')

Inside the handler, this is the element, as in jQuery.

The jump: stop commanding, start describing

A counter in jQuery:

let count = 0;
$('#counter .plus').on('click', function () {
  count++;
  $('#counter .value').text(count);
  $('#counter .minus').prop('disabled', count === 0);
});
$('#counter .minus').on('click', function () {
  count--;
  $('#counter .value').text(count);
  $('#counter .minus').prop('disabled', count === 0);
});

The same thing in Voodoo.js:

<div v-data="{ count: 0 }">
  <button @click="count--" :disabled="count === 0">-</button>
  <span>{ count }</span>
  <button @click="count++">+</button>
</div>

The rule "the minus button is disabled at zero" appears once, in the place where it matters. In jQuery it had to be repeated everywhere the value changed, and forgetting one repetition was the classic bug.

A list

// jQuery
function render(items) {
  const $ul = $('#list').empty();
  items.forEach((item) => {
    $ul.append('<li data-id="' + item.id + '">' + item.name + ' <button class="x">remove</button></li>');
  });
}
$('#list').on('click', '.x', function () {
  const id = $(this).closest('li').data('id');
  items = items.filter((i) => i.id !== id);
  render(items);
});
<ul v-data="{ items: [{ id: 1, name: 'Mug' }, { id: 2, name: 'Shirt' }] }">
  <li v-for="item in items" :key="item.id">
    { item.name }
    <button @click="items.splice(items.indexOf(item), 1)">remove</button>
  </li>
</ul>

There is no render function. There is no delegation. There is no data-id whose only job is finding the item again.

An AJAX form

// jQuery
$('#form').on('submit', function (e) {
  e.preventDefault();
  const $btn = $(this).find('button').prop('disabled', true).text('Sending...');
  $.post('/api/contact', $(this).serialize())
    .done(() => { alert('Sent!'); this.reset(); })
    .fail((xhr) => { $('#error').text(xhr.responseJSON.message); })
    .always(() => { $btn.prop('disabled', false).text('Send'); });
});
<form v-submit="/api/contact" v-validate v-reset-success v-disable-loading
      v-toast-success="Sent!">
  <input name="name" v-required>
  <input name="email" type="email" v-required v-email>
  <button>{ $form.loading ? 'Sending...' : 'Send' }</button>
</form>

Validation, loading state, per-field errors and the notification all come together.

jQuery plugins

A plugin that needs an element becomes a directive:

// jQuery
$('.date').datepicker({ format: 'dd/mm/yyyy' });

// Voodoo.js
V.directive('datepicker', {
  mounted(el, binding) {
    el.__picker = new YourDatepicker(el, { format: binding.value || 'dd/mm/yyyy' });
  },
  unmounted(el) { el.__picker.destroy(); }
});
<input v-datepicker="'dd/mm/yyyy'">
Where to start the migration

Replace first the parts that suffer most from manual synchronization: lists that filter, forms, and any state that shows up in two places. The rest of the jQuery code keeps running alongside, and you convert it when you are going to touch it anyway.
