Qualidade e migração

Migrando do Vue

A sintaxe de template foi desenhada para ser familiar a quem vem do Vue: directives, modificadores, v-model e o modelo de componentes seguem os mesmos nomes. A diferença de fundo é que não existe compilação — a Voodoo interpreta o HTML que já está na página. Isso muda o que é possível; vale ler a seção de limites antes de decidir.

createApp

A montagem tem o mesmo formato, e as mesmas opções de componente na raiz: 

// Vue
createApp({ data: () => ({ n: 0 }), template: '<b>{{ n }}</b>' }).mount('#app');

// Voodoo.js
V.createApp({ data: () => ({ n: 0 }), template: '<b>{ n }</b>' }).mount('#app');

O guia de os dois modos explica quando usar createApp e quando ficar nos atributos.

Modificadores

.prevent, .stop, .self, .once, .capture, .passive, as teclas e .ctrl, .shift, .alt, .meta são iguais. Do v-model, .lazy, .number e .trim também.

Não existem: .exact e os modificadores de botão do mouse (.left, .right, .middle). Existem só aqui: .window, .document, .outside, .debounce e .throttle.

Reatividade

reactive, ref, shallowRef, computed (também na forma { get, set }), watch, watchEffect, effectScope, nextTick, toRaw, markRaw, unref e isReactive existem com o mesmo nome, em V. As opções de watch são as mesmas: immediate, deep e flush com pre, post e sync.

Duas ausências que pegam de surpresa

Não existem readonly, shallowReactive, toRefs e customRef. E não existe desembrulho automático de ref no template: dentro da expressão, use .value.

Transições

<!-- Vue -->

<!-- Voodoo.js -->

As classes seguem o mesmo padrão: v-fade-enter-from, v-fade-enter-active, v-fade-enter-to, e as três equivalentes de saída.

O que não existe, e por quê

A Voodoo interpreta o HTML da página. Sem compilação, algumas coisas do Vue não têm como existir:

  • componentes de arquivo único (.vue), que dependem de um compilador;
  • JSX e funções de render;
  • setup(), a Composition API e <script setup>;
  • renderização no servidor com hidratação;
  • slots com escopo, que passam dados do filho para o conteúdo do pai;
  • <KeepAlive>, <Suspense> e v-memo;
  • desembrulho automático de ref no template;
  • checagem de tipos no template.

As expressões também aceitam um subconjunto de JavaScript: sem function, class, new, delete, await, laços e desestruturação. A referência de expressões lista o que entra.

O que você ganha

  • Nenhum passo de build. Nada de bundler, configuração ou node_modules para colocar uma página no ar.
  • Um arquivo só, que você baixa e serve do seu próprio domínio.
  • Muita coisa embutida: HTTP declarativo, formulários com validação e máscaras, interface, arrastar e soltar, armazenamento, notificações — e no build completo gráficos, animações, roteador e idiomas.
  • Funciona com CSP restritiva, sem unsafe-eval.
  • Convive com HTML gerado no servidor, sem precisar assumir a página inteira.

Quando não trocar

Se o seu projeto tem dezenas de telas, um time grande, testes de componente e tipagem estrita nos templates, o Vue continua sendo a escolha certa. A Voodoo foi feita para o outro lado da balança: páginas geradas no servidor, painéis administrativos, protótipos e times pequenos.

Convivendo

As duas podem rodar na mesma página, em áreas diferentes. Marque a região do Vue com v-ignore para que a Voodoo não toque nela: 

<div id="app-vue" v-ignore></div>

<div v-data="{ n: 0 }">
  <button @click="n++">{ n }</button>
</div>
