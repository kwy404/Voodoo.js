Regras de validação

Todas existem como directive curta (v-nome) e como v-validate-nome. O guia de formulários mostra o conjunto funcionando; aqui está a lista completa.

Quando cada checagem acontece

Cada campo é validado quando perde o foco. Depois do primeiro erro, ele passa a revalidar a cada tecla, o que dá retorno imediato sem incomodar quem ainda está digitando. No envio por v-submit, o formulário inteiro é validado: se algo reprovar, o envio para, o foco vai para o primeiro campo com problema e o evento voodoo:invalid é disparado.

Um campo isolado, fora de um formulário validado, também funciona: basta declarar a regra, ou usar v-validate no próprio campo.

O que aparece na tela

  • o campo ganha a classe v-invalid e aria-invalid="true";
  • uma mensagem com role="alert" entra logo depois dele, com a classe v-field-error;
  • aria-describedby aponta para a mensagem;
  • quando aprova, o campo ganha v-valid e a mensagem é removida.
<input name="email" v-required v-email v-error-target="#erro-do-email">
<span id="erro-do-email"></span>

Atributos nativos também valem

<input required minlength="3" maxlength="20" pattern="[a-z]+">
<input type="email" required>
<input type="number" min="1" max="10">
<input type="url">

A biblioteca lê os atributos padrão do HTML e os transforma em regras, o que permite adotar a validação em um formulário existente sem reescrever nada.

Desligando uma regra

<input name="cnpj" v-cnpj v-required="false">

O valor é lido do atributo original, então a decisão acontece na renderização e não muda depois. Para uma regra que liga e desliga em tempo real, escreva uma regra própria que consulte o estado.

Mensagens

Object.assign(V.messages, {
  required: 'Campo obrigatório.',
  email: 'Confira o e-mail digitado.',
  minlength: 'Escreva pelo menos {param} caracteres.'
});
MarcadorVira
{param}O parâmetro da regra
{field}O rótulo do campo
{value}O valor digitado
{min}, {max}As duas partes de um parâmetro como 10,100

O rótulo do campo é descoberto nesta ordem: v-label, o <label for> correspondente, o texto do <label> em volta, aria-label, placeholder e por fim o name.

As chaves de V.messages são: required, email, url, number, integer, decimal, alpha, alphanumeric, minlength, maxlength, min, max, between, match, regex, date, after, before, accepted, same, different, in, notin, phone, cpf, cnpj, cep, creditcard, strongpassword, unique e invalid.

Validação assíncrona

<input name="email" type="email" v-required v-email v-validate-unique="/api/checar-email">
<input name="apelido" v-validate-unique v-unique-url="/api/checar-apelido">

A biblioteca chama GET /api/checar-email?value=...&field=email e espera:

  • { "available": true } para liberar;
  • { "available": false } para reprovar;
  • resposta vazia ou null para liberar;
  • qualquer outro corpo para reprovar, entendendo que o registro existe;
  • status 404 para liberar.
Falha de rede não trava o envio

Se a consulta não completa, a regra libera e deixa o servidor decidir na hora do POST. É a escolha certa: um problema de rede não pode impedir alguém de tentar se cadastrar.

Regras próprias

V.validator('par', (valor) => Number(valor) % 2 === 0, 'Informe um número par.');

A função recebe (valor, parametro, elemento) e pode devolver true para aprovar, false para reprovar com a mensagem padrão, um texto para reprovar com aquela mensagem, ou uma Promise de qualquer um dos três. 

V.validator('cnpjAtivo', async (valor) => {
  if (!valor) return true;
  const dados = await V.http.get('/api/cnpj/' + V.unmask(valor));
  return dados.ativo ? true : 'Este CNPJ está inativo na Receita.';
});

V.validator('depoisDe', (valor, param, el) => {
  const outro = document.querySelector('[name="' + param + '"]');
  return !outro || valor > outro.value || 'Precisa ser depois de ' + outro.value;
});

Registrar uma regra cria automaticamente a directive v-validate-<nome>.
