Reference

Validation rules

Every one of them exists as a short directive (v-name) and as v-validate-name. The forms guide shows the set working; here is the complete list.

When each check happens

Each field is validated when it loses focus. After the first error, it starts revalidating on every keystroke, which gives immediate feedback without bothering someone who is still typing. On submit through v-submit, the whole form is validated: if anything fails, the submit stops, focus moves to the first field with a problem and the voodoo:invalid event is fired.

A lone field, outside a validated form, works too: just declare the rule, or use v-validate on the field itself.

What shows up on screen

  • the field gets the class v-invalid and aria-invalid="true";
  • a message with role="alert" goes in right after it, with the class v-field-error;
  • aria-describedby points at the message;
  • when it passes, the field gets v-valid and the message is removed.
<input name="email" v-required v-email v-error-target="#email-error">
<span id="email-error"></span>

Native attributes count too

<input required minlength="3" maxlength="20" pattern="[a-z]+">
<input type="email" required>
<input type="number" min="1" max="10">
<input type="url">

The library reads the standard HTML attributes and turns them into rules, which lets you adopt validation in an existing form without rewriting anything.

Turning a rule off

<input name="cnpj" v-cnpj v-required="false">

The value is read from the original attribute, so the decision happens at render time and does not change afterwards. For a rule that turns on and off in real time, write a rule of your own that consults the state.

Messages

Object.assign(V.messages, {
  required: 'This field is required.',
  email: 'Check the email you typed.',
  minlength: 'Write at least {param} characters.'
});
PlaceholderBecomes
{param}The rule's parameter
{field}The field's label
{value}The value typed
{min}, {max}The two halves of a parameter like 10,100

The field label is found in this order: v-label, the matching <label for>, the text of the <label> around it, aria-label, placeholder and finally name.

The keys of V.messages are: required, email, url, number, integer, decimal, alpha, alphanumeric, minlength, maxlength, min, max, between, match, regex, date, after, before, accepted, same, different, in, notin, phone, cpf, cnpj, cep, creditcard, strongpassword, unique and invalid.

Asynchronous validation

<input name="email" type="email" v-required v-email v-validate-unique="/api/check-email">
<input name="nickname" v-validate-unique v-unique-url="/api/check-nickname">

The library calls GET /api/check-email?value=...&field=email and expects:

  • { "available": true } to pass;
  • { "available": false } to fail;
  • an empty response or null to pass;
  • any other body to fail, taking it that the record exists;
  • status 404 to pass.
A network failure does not block the submit

If the request does not complete, the rule passes and lets the server decide at POST time. It is the right call: a network problem cannot be what stops someone from trying to sign up.

Rules of your own

V.validator('even', (value) => Number(value) % 2 === 0, 'Enter an even number.');

The function receives (value, parameter, element) and can return true to pass, false to fail with the default message, a string to fail with that message, or a Promise of any of the three. 

V.validator('activeCnpj', async (value) => {
  if (!value) return true;
  const data = await V.http.get('/api/cnpj/' + V.unmask(value));
  return data.active ? true : 'This CNPJ is inactive at the Receita.';
});

V.validator('afterField', (value, param, el) => {
  const other = document.querySelector('[name="' + param + '"]');
  return !other || value > other.value || 'Must be after ' + other.value;
});

Registering a rule automatically creates the directive v-validate-<name>.

From JavaScript

const result = await V.validate(document.forms[0]);
// { valid: true, errors: {} }

const field = await V.validate(document.querySelector('#email'));
// { valid: false, message: 'Enter a valid email.', rule: 'email' }

V.showFieldError(input, 'A specific message');
V.showFormErrors(form, { email: 'Already registered' });
V.clearErrors(form);

V.validateForm is an alias of V.validate for forms. It is what you call when the submit is handled on your own, with @submit.prevent, and you still want the final check before going ahead.
