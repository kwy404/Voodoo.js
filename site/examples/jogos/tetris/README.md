# Tetris

A complete Tetris: a seven-piece bag, ghost piece, hold, wall kicks, a grace
period before the piece locks, clear streaks, a level that speeds up every ten
lines, pause, a persisted high score and synthesized sound.

Open it at `http://localhost:5173/examples/jogos/tetris/`.

## What this demo shows of Voodoo.js

Tetris went into this folder precisely because it has **a lot of interface**:
score, lines, level, high score, tetris count, the queue of upcoming pieces, the
held piece, the last move, the streak, menus, pause and game over.

**The preview pieces are not canvas.** Each one is a 4x4 grid of `<span>`
generated by a nested `v-for`, with the color coming in through `:style`. When
the queue advances, Voodoo redraws the cells. It is the most direct example of
"game data turning into markup" that the demo has.

**The board is canvas**, because there it is two hundred cells per frame, plus
the ghost piece, the danger line and the line-clear particles.

**The contract between the two:** the play grid (`mundo.grade`), the current
piece and the piece bag live in plain objects, created in `mounted` and left
outside the reactive state on purpose. Only what the interface shows is a
property of the component. That way the physics runs at 60 frames per second
without triggering a single DOM update, and the HUD stays declarative.

## One detail worth noticing

The responsive behavior also comes out of the state, not only out of the CSS.
`redimensionar` writes `estreito` when the window drops below 720px, and the
computed `proximasVisiveis` cuts the queue from four pieces down to two. In
other words: the generated markup really changes, instead of hiding elements
with `display: none`.

## Features used

| Feature | Where |
| --- | --- |
| `v-component` | the whole game, registered with `V.component` |
| nested `v-for` | the queue of upcoming pieces and each 4x4 grid |
| `v-show` | the start, pause and game over screens |
| `:style`, `:class` | the color of each cell, the screen shake, the locked held piece |
| `computed` | `gradeGuardada`, `proximasVisiveis`, the screen reader description |
| `v-ref` / `$refs` | access to the `<canvas>` |
| `V.storage` | the persisted high score |
| `V.sound` | five effects defined with `V.sound.define` |
| `v-mute`, `v-theme-toggle` | sound and theme, with no JavaScript of your own |

## Controls

| Key | Action |
| --- | --- |
| `←` `→` | move (with auto repeat) |
| `↓` | drop faster |
| `↑` or `X` | rotate |
| `Z` | rotate the other way |
| `Space` | hard drop |
| `C` or `Shift` | hold the piece |
| `P` or `Esc` | pause |
| `R` | restart |

On a phone there are six large buttons, and the board also takes gestures:
swiping sideways moves, swiping down drops, and a short tap rotates.

## Behavior

- The loop is canceled on `beforeUnmount` and on `pagehide`; every listener goes
  with it. Leaving the tab pauses the game.
- `prefers-reduced-motion` turns off the shake and the interface transitions.
- The canvas carries an `aria-label` describing the state of the match, and each
  mini piece has `role="img"` with the name of the piece.
